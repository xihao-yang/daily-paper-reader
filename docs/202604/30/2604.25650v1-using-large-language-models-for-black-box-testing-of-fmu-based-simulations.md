## 摘要
我们提出一种基于大语言模型（LLMs）的“人机协同”方法，用于对功能模型单元（Functional Mock-up Units，FMUs）进行黑箱测试。该方法的目标是减少在为动态仿真模型定义测试场景时的人工工作量，并提高结果的可解释性。具体而言，该方法以FMU的功能和接口规范为输入，提示LLM生成采用“Given-When-Then”格式的结构化场景目标，用以定义仿真的初始输入条件、这些条件的可能变化以及系统在这些变化下的预期输出行为。相应的场景计划进一步指定输入模式，并添加断言预言机，用以描述在场景目标中定义的预期输出模式。该方法生成场景计划的完整输入时间序列，运行FMU仿真，并在记录的输出上评估断言。它生成可供人阅读的日志和图表，展示每个场景的统计数据（包括叠加图）、总体通过率和各目标的结果。生成的场景和结果被存储以便评估及后续重新执行。我们在润滑油冷却系统上对该方法进行了评估，并讨论了使该方法适用于日常使用的设计选择。结果表明，基于LLM的场景生成可以促进动态仿真模型的自动测试设计与验证。

## Abstract
We propose a human in the loop approach for black-box testing of Functional Mock-up Units (FMUs) using Large Language Models (LLMs). The goal is to reduce the manual effort in defining test scenarios for dynamic simulation models and to improve the interpretability of results. The approach takes the functional and interface specifications of an FMU as input, and prompts an LLM to generate structured scenario goals in Given-When-Then format that define the initial input conditions of the simulation, a possible change in those conditions, and the expected output behaviour of the system against those changes. The corresponding scenario plans specify input patterns and add assertion oracles that describe expected output patterns defined in scenario goals. The approach generates a complete input time series for the scenario plans, runs the FMU simulation, and evaluates assertions on the recorded outputs. It produces human-readable logs and plots that show statistics for each scenario with overlays, aggregate pass rates, and per-goal outcomes. The generated scenarios and results are stored for evaluation and later re-execution. We evaluate the approach on a Lube Oil Cooling system and discuss design choices that make the approach practical for everyday use. Results suggest that LLM-assisted scenario generation can facilitate automatic test design and verification of dynamic simulation models.

## 一、核心问题与整体含义

- **研究动机**  
  随着工程系统向模型驱动设计（Model-Based Design, MBD）转变，组件的验证多通过仿真完成。为了实现跨工具的模型交换与协同仿真，**功能模型接口（FMI）标准**被广泛应用，用于封装模型为功能模型单元（FMU）。  
  然而，FMU 的内部结构和方程往往不可访问，使得传统的**白箱测试**方法失效，测试者只能依赖接口描述文件 (`modelDescription.xml`) 和规范文档。这种依赖导致测试场景构建耗时、覆盖率不足。  
  因此，作者提出利用大型语言模型（LLMs）自动**生成黑箱测试场景**，减少人工工作量，提高测试自动化和结果解释性。

- **研究目标**  
  设计一个人机协同的测试流程，通过 LLM 生成“Given–When–Then”（GWT）模式的场景目标和场景计划，实现 FMU 仿真测试的自动化与高可解释输出。

## 二、方法论：核心思想与技术流程

### 核心思想
- 使用 LLM 从 FMU 的功能规范与接口文档中提取 I/O 约束；
- 利用结构化提示工程（Prompt Engineering）生成 GWT 格式的测试目标；
- 将目标转化为可执行的场景计划（Scenario Plans），自动生成断言预言机（Oracle）；
- 运行仿真并基于自动断言判定测试结果；
- 人类专家参与审查与反馈，实现“人机协同”质量保证。

### 技术流程（可视化于原论文 Fig. 1）
1. **FMU 元数据提取**：解析 `modelDescription.xml` 提取输入输出变量、单位、约束范围。  
2. **场景生成三阶段**：  
   - **目标层（Goal Generation）**：LLM 根据系统规格生成 GWT 格式的场景描述。  
   - **计划层（Plan Generation）**：将目标转化为具体参数空间、输入模式（常量、步进、线性变化），并生成断言类型。  
   - **场景层（Scenario Execution）**：使用拉丁超立方抽样（Latin Hypercube Sampling, LHS）生成输入时间序列并执行仿真。
3. **断言预言机（Oracles）**  
   定义多种定性行为判定算子：`bounded`, `monotonic_increase`, `settles_to`, `crosses_above` 等，用于验证数值趋势而非具体值。  
4. **数据校验与去重机制**：基于哈希检测重复目标/计划，确保唯一性与可追踪性。  
5. **人类反馈环**：专家检查不合理目标或计划，修正提示模板（prompt refinement）。  
6. **仿真执行与结果汇总**：自动运行 FMU，输出统计报告、覆盖率、通过率与日志。

## 六、主要结论与发现

- **LLM可有效自动生成黑箱测试场景**，从接口数据中提取测试目标与断言；
- 加入**人机协同环节**后，场景质量与合理性显著提升；
- 生成的自动化场景与人工场景在故障检测能力上相当（mutation score ≈ 0.67 vs 0.685）；
- 提示工程（schema‑first + few‑shot）和温度分层策略有效提升结构与覆盖率；
- 方法实现了测试全流程的自动化（提取、设计、执行、评估），提升效率与可解释性。

## 七、优点与亮点

- ✅ **创新性人机协同测试框架**：将LLM引入FMU黑箱测试并保留人类专家监督。

- ✅ **多层场景抽象**（Goal→Plan→Scenario），实现语义一致性与可追踪性。  
- ✅ **自动断言预言机制**：用定性变化趋势替代具体数值，适合黑箱验证环境。  
- ✅ **去重与确定性机制**：利用哈希和固定随机种子保证可复现性。  
- ✅ **低计算成本高可扩展性**：无需深度模型训练即可应用于任意FMU。

## 八、不足与局限

- ⚠ **非确定性问题**：LLM的随机采样可能导致相同条件下输出不同场景。  
- ⚠ **幻觉与错误风险**：部分参数范围或JSON结构不符合规范，需人工筛查。  
- ⚠ **场景覆盖有限**：仅在单一FMU上验证，缺乏多系统或复杂模型测试。  
- ⚠ **定性断言的有效性问题**：阈值和时间窗口的设定可能导致误判。  
- ⚠ **依赖专家反馈**：虽然减少人工编写，但仍需要专家参与审核与prompt微调。  
- ⚠ **可复现性受限**：LLM非完全可重复，温度变化引起结果波动。  
- ⚠ **未来扩展挑战**：多FMU协同、共仿真环境尚未实现，需要更复杂的数据驱动校准。
