## 摘要
反编译——从已编译的二进制文件中恢复源代码——对于安全分析、恶意软件逆向工程和遗留软件维护至关重要。然而，现有的反编译器生成的代码往往无法正确编译或执行，限制了其实际效用。我们提出了一个多智能体框架，通过多层约束引导反编译（Multi-level Constraint-Guided Decompilation，MCGD）将反编译代码转化为可重新执行的源代码。我们的方法采用分层验证管线，包含三个约束层级：（1）通过解析实现语法正确性，（2）通过 GCC 实现可编译性，（3）通过大型语言模型生成的测试用例实现行为等价。当验证失败时，专门的 LLM 智能体会利用结构化的错误反馈迭代改进代码。我们在 ExeBench 数据集的 1,641 个真实世界二进制文件上评估了该框架，涉及三个反编译器（RetDec、Ghidra 和 Angr）。我们的框架实现了 84–97% 的可重新执行性，相较基线反编译器输出提升了 28–89 个百分点。与使用相同 GPT-4o 主干的最先进 LLM 反编译方法相比，我们的方法（84.1%）优于 LLM4Decompile（80.3%）、SK2Decompile（73.9%）和 SALT4Decompile（61.8%）。消融研究表明，基于执行的验证至关重要：仅编译的方法虽然达到 91–99% 的编译率，但行为正确性为 0%。系统高效收敛，超过 90% 的二进制文件在两次迭代内达到正确性，平均成本为每个二进制文件 $0.03–0.05。我们的结果表明，约束引导的智能体优化能够有效弥合原始反编译输出与实际可用源代码之间的差距。

## Abstract
Decompilation -- recovering source code from compiled binaries -- is essential for security analysis, malware reverse engineering, and legacy software maintenance. However, existing decompilers produce code that often fails to compile or execute correctly, limiting their practical utility. We present a multi-agent framework that transforms decompiled code into re-executable source through Multi-level Constraint-Guided Decompilation (MCGD). Our approach employs a hierarchical validation pipeline with three constraint levels: (1) syntactic correctness via parsing, (2) compilability via GCC, and (3) behavioral equivalence via LLM-generated test cases. When validation fails, specialized LLM agents iteratively refine the code using structured error feedback. We evaluate our framework on 1,641 real-world binaries from ExeBench across three decompilers (RetDec, Ghidra, and Angr). Our framework achieves 84-97% re-executability, improving baseline decompiler output by 28-89 percentage points. In comparison with state-of-the-art LLM-based decompilation methods using the same GPT-4o backbone, our approach (84.1%) outperforms LLM4Decompile (80.3%), SK2Decompile (73.9%), and SALT4Decompile (61.8%). Our ablation study reveals that execution-based validation is critical: compile-only approaches achieve 0% behavioral correctness despite 91-99% compilation rates. The system converges efficiently, with 90%+ binaries reaching correctness within 2 iterations at an average cost of $0.03-0.05 per binary. Our results demonstrate that constraint-guided agentic refinement can bridge the gap between raw decompiler output and practically useful source code.

## 一、研究背景与核心问题

- **研究动机**  
  反编译旨在从已编译的二进制可执行文件恢复高层源代码，是软件安全、漏洞分析、恶意软件逆向与遗留代码维护的关键技术。  
  当前主流反编译器（如 Ghidra、IDA Pro、RetDec 等）虽然能生成可读源代码，但**编译率高而行为正确率低**。生成的代码常包含：
  - 语法错误与类型定义缺失；
  - 错误的控制流或数据流；
  - 即使能编译，也无法再现原始二进制的行为。  

- **核心问题**  
  传统反编译的最大瓶颈是：编译成功 ≠ 行为正确。编译器优化导致源码到二进制的信息大量丢失，使得反编译难以恢复语义一致的可执行代码。现有 LLM 方法虽然能生成格式化代码，但大多为单次生成，缺乏有效反馈机制。  

- **研究目标**  
  提出一种基于多智能体与多级约束的反编译后处理框架，实现**从不可执行的反编译输出 → 可编译且行为等价的源代码**转换，提升可重编译与再执行能力。

## 二、方法论与技术框架

### 1. 核心思想
- 将反编译视为一个**多层约束搜索与修复问题**；
- 通过层级化验证信号（语法 → 编译 → 执行）逐步缩小搜索空间；
- 各层失败时由专用 LLM 智能体利用结构化错误反馈修复代码；
- 使用行为等价测试（re-executability）作为最终正确性指标。

### 2. 系统总体框架（Agent4Decompile）
- **输入**：反编译器生成的初始 C 代码；
- **处理管线**：
  1. **L1（语法层）**：验证是否可被解析为合法 C 语言；
  2. **L2（编译层）**：验证是否能通过 GCC 编译；
  3. **L3（执行层）**：将编译结果在测试输入上执行，比较输出与原二进制行为；
- **智能体配置**：
  - 三个专用 LLM agent 分别对应三个层级；
  - 每个 agent 接收错误反馈（语法错误、编译器诊断、失败的 I/O 测试样例）；
  - 输出修正后的代码，重新进入验证循环；  
  - 算法最多迭代七次，一般两次内收敛。

### 3. 形式化描述
定义三个约束函数：
\[
φ_1(C)：语法可解析；\quad φ_2(C)：编译成功；\quad φ_3(C,T)：执行输出等价。
\]
算法流程（简化文字版）：
1. 对二进制文件进行初次反编译获得代码 \(C_0\)；
2. 依次验证 (L1→L2→L3)；
3. 若某层失败，调用对应 Agent 修复；
4. 修复后重新验证直至全部通过或达迭代上限。

### 4. 技术实现细节
- 编译与验证基于 **GCC 11.4**；
- 运行环境具备沙箱控制（10s 超时，256MB 内存限制）；
- 默认 LLM 模型为 **DeepSeek V3.2**（temperature=0.0，max token 4096）；
- 使用多进程加速批量处理，所有日志与交互均完整记录以确保可复现性。
