## 摘要
用于自动化程序修复的自主代理代表了软件工程中的一个有前景的前沿方向，但它们的有效性常常受到依赖事后、粗粒度执行反馈的限制。虽然将传统的交互式调试器整合进来似乎是一个自然的解决方案，但其低层次、逐行交互的范式对于基于大型语言模型（LLM）的代理来说成本效率低下，导致预算耗尽和无效循环。为了解决这一问题，我们提出了 Agent-centric Debugging Interface（ADI），一种面向代理的全新调试接口，旨在实现高性价比的端到端自主交互。具体而言，Agent-centric Debugging Interface 实现了一种基于函数级别的交互范式，由我们提出的 Frame Lifetime Trace 提供支持——这一全面的数据结构封装了函数的状态执行轨迹，并配备一组高级导航命令。我们在 SWE-bench 基准上的广泛评测证明了 ADI 的有效性和效率。仅通过为一个基础代理配备 ADI，它即可在 SWE-bench Verified 数据集上成功解决 63.8% 的任务，甚至略微超越经过高度优化且投入巨大的 Claude-Tools 代理，并在使用 Claude-Sonnet-3.7 时实现了每个任务平均成本为 1.28 美元。此外，我们通过将 ADI 作为即插即用组件整合进现有的最先进（SOTA）代理中，展示了其普适性，在已解决任务比例上带来了 6.2% 至 18.5% 的持续提升。这些结果表明，Agent-centric Debugging Interface 能为现有自主代理提供一种通用而高效的增强。

## Abstract
Autonomous agents for automated program repair represent a promising frontier in software engineering, yet their effectiveness is often hindered by reliance on post-mortem, coarse-grained execution feedback. While integrating traditional interactive debuggers seems a natural solution, their low-level, line-by-line interaction paradigm turns out to be cost-inefficient for LLM-based agents, leading to exhausted budgets and unproductive loops. To mitigate this, we introduce Agent-centric Debugging Interface (ADI), a novel agent-centric debugging interface designed for cost-efficient, end-to-end autonomous interaction. Specifically, Agent-centric Debugging Interface realizes a function-level interaction paradigm, powered by our Frame Lifetime Trace, a comprehensive data structure encapsulating a function's stateful execution trace, and a set of high-level navigational commands. Our extensive evaluation on the SWE-bench benchmark demonstrates the effectiveness and efficiency of ADI. By simply equipping a basic agent with ADI, it successfully resolves 63.8\% of the tasks on the SWE-bench Verified set, even slightly outperforming the highly optimized and high-investment Claude-Tools agent, at an average cost of USD 1.28 per task with Claude-Sonnet-3.7. Furthermore, we demonstrate ADI's generality by integrating it as a plug-and-play component into existing SOTA agents, delivering consistent gains ranging from 6.2\% to 18.5\% on the resolved tasks. These results indicate that Agent-centric Debugging Interface can provide a general and efficient enhancement for existing autonomous agents.

## 二、方法论：Agent-centric Debugging Interface (ADI)

### 1. 核心思想
ADI 是一个**面向代理的交互式调试接口**，不同于传统行级调试器，它采用**函数级（function-level）交互模型**。  
其设计理念包括：
- 为 LLM 提供高语义、低频率的信息交互；
- 利用函数帧（Function Frame）作为分析单元；
- 实现高效的动态执行状态采集与导航。

### 2. 关键组件

#### （1）Frame Lifetime Trace (FLT)
一个封装函数执行全过程的数据结构，用于捕获函数的状态变化。  
其形式为：
\[
FLT = (fid, fid_{caller}, args, ret, \tau)
\]
其中：
- **fid**：当前函数标识；
- **fid_{caller}**：调用者帧标识；
- **args/ret**：函数参数与返回值；
- **τ（语句执行轨迹）**：记录语句编号、内容、状态变化 ΔS、被调用函数等信息。

#### （2）高层次命令接口
ADI 提供一组函数级调试命令：
- `break(func, [condition])`：设置函数级条件断点；  
- `continue()/prev()`：在断点间前后跳转；  
- `step-into(fid)/step-out()`：在调用栈间上下导航；  
- `call-tree()`：生成函数调用树；  
- `execute(fid, stmt, lineno, k)`：在指定上下文中执行语句，实现“what-if”分析。

#### （3）交互循环算法（ADI Interaction Loop）
- **FrameLifetimeTracer**：对函数运行时进行按需插桩，生成对应 FLT；
- **ADI_Interaction_Loop**：依据代理命令维护调试状态 Σ = (B, T, i)，
并动态生成所需 FLT 以反馈给代理；
- 该算法实现“惰性分析”：仅在代理关注的函数帧上细粒度跟踪，减少全局性能消耗。

### 1. 数据集与场景

### 2. 对比基线

- Claude-Tools（Claude 官方高投资代理）

- **BaseAgent**：仅事后调试；
- **BaseAgentₚdb**：使用传统行级调试（PDB）；

### 3. 指标与设定
- **主指标**：Resolved Rate (Pass@1)
- **辅助指标**：
  - Average Cost（美元/任务）
  - Correct Location Rate（补丁位置正确率：行/函数/文件级）
- 所有实验遵循 SWE-bench 官方 Docker 环境，设定统一温度（0），预算上限 $4/任务。

## 八、不足与局限

- **场景局限**：  
  仅在 Python 环境验证，虽原理可迁移至其他语言，但需额外插桩支持。
- **bug 类型限制**：  
  ADI 更适合依赖数据流与控制流分析的逻辑错误，但对并发、资源泄漏等难以直接适应。
- **性能影响**：  
  尽管采用选择性插桩，仍提高执行时间（0.68s→0.87s）；多次重执行可能引入随机性。
- **再执行依赖**：  
  On-demand tracing 机制依赖可重现环境；若程序存在非确定性，会影响一致性。
- **缺乏跨语言或工业场景评估**，仍需进一步验证可扩展性。
