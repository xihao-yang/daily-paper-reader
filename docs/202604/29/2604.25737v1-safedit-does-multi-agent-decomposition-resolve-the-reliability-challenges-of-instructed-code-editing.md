## 摘要
在指令驱动的代码编辑任务中，大型语言模型（LLMs）面临重大挑战。在 EditBench 基准上，40 个被评估模型中有 39 个的任务成功率（TSR）低于 60%，这凸显了通用代码生成与在可执行测试约束下进行基于指令的编辑能力之间的差距。为此，我们提出 SAFEdit——一种多智能体框架，用于指令性的代码编辑，通过将编辑过程拆分为专门的角色来提升可靠性并减少非预期的代码改动。规划智能体（Planner Agent）生成显式且具可见性的编辑计划，编辑智能体（Editor Agent）进行最小化的字面代码修改，验证智能体（Verifier Agent）执行真实的测试运行。当测试失败时，SAFEdit 通过故障抽象层（Failure Abstraction Layer, FAL）将原始测试日志转换为结构化的诊断反馈，并反馈给编辑智能体以支持迭代优化。我们在相同评估条件下，将 SAFEdit 与 EditBench 上先前的单模型结果以及一个实现的 ReAct 单智能体基线进行了比较。我们使用 EditBench 在五种语言（英语、波兰语、西班牙语、中文和俄语）及不同空间上下文变体下评估了 SAFEdit，共计 445 个代码编辑实例。SAFEdit 的任务成功率达到 68.6%，比单模型基线提高 3.8 个百分点，比 ReAct 单智能体基线提高 8.6 个百分点。迭代优化循环对 SAFEdit 的总体成功率贡献了 17.4 个百分点。SAFEdit 的自动化错误分析进一步表明，相较于单智能体方法，它减少了指令层面的幻觉现象，并提供了一个额外的框架组件，用于解释超越通过/失败结果的错误。

## Abstract
Instructed code editing is a significant challenge for large language models (LLMs). On the EditBench benchmark, 39 of 40 evaluated models obtain a task success rate (TSR) below 60 percent, highlighting a gap between general code generation and the ability to perform instruction-driven editing under executable test constraints. To address this, we propose SAFEdit, a multi-agent framework for instructed code editing that decomposes the editing process into specialized roles to improve reliability and reduce unintended code changes. A Planner Agent produces an explicit, visibility-aware edit plan, an Editor Agent applies minimal, literal code modifications, and a Verifier Agent executes real test runs. When tests fail, SAFEdit uses a Failure Abstraction Layer (FAL) to transform raw test logs into structured diagnostic feedback, which is fed back to the Editor to support iterative refinement. We compare SAFEdit against both prior single-model results reported for EditBench and an implemented ReAct single-agent baseline under the same evaluation conditions. We used EditBench to evaluate SAFEdit on 445 code editing instances in five languages (English, Polish, Spanish, Chinese, and Russian) under varying spatial context variants. SAFEdit achieved 68.6 percent TSR, outperforming the single-model baseline by 3.8 percentage points and the ReAct single-agent baseline by 8.6 percentage points. The iterative refinement loop was found to contribute 17.4 percentage points to SAFEdit's overall success rate. SAFEdit's automated error analysis further indicates a reduction in instruction-level hallucinations compared to single-agent approaches, providing an additional framework component for interpreting failures beyond pass or fail outcomes.

## 一、研究背景与核心问题

- **研究动机**  
  当前大语言模型（LLMs）虽在代码生成任务中表现优秀，但在**基于自然语言指令的代码编辑（Instructed Code Editing）**场景中表现明显不足。  
  - 在 EditBench 基准上，40 个模型中有 39 个任务成功率（TSR）低于 60%。  
  - 原因在于该任务需要模型不仅能理解自然语言指令，还需精准修改已有程序且保持原逻辑与语义不变，这比直接生成代码更复杂。  

- **核心问题**  
  如何让 LLM 在已有代码基础上执行“可靠、精确、可验证”的编辑操作，避免“幻觉性更改”或破坏现有功能。

- **研究目标**  
  提出一种结构化框架，使 LLM 能：
  1. 正确理解编辑意图。  
  2. 实现最小必要修改。  
  3. 利用真实测试验证修订结果的正确性。

## 二、方法论与核心思想

### 1. 框架总体设计  

论文提出**SAFEdit（Structured Agentic Framework for Trustworthy Code Editing）**，一个多智能体系统，将代码编辑流程拆分为三个角色：

1. **Planner Agent（规划智能体）**  
   - 负责分析自然语言指令，生成结构化的“编辑计划”（edit plan）。
   - 不直接生成代码，只确定应修改的位置、目标与约束。  
   - 输出包括：可见代码实体、编辑意图、修改点描述、修改操作列表、约束条件。

2. **Editor Agent（编辑智能体）**  
   - 根据规划结果执行字面修改（literal editing），尽量最小化变动并保持格式。  
   - 禁止额外推理或自由发挥，防止“过度编辑”现象。  

3. **Verifier Agent（验证智能体）**  
   - 运行真实的单元测试（非模型预测），收集执行日志作为真实反馈信号。  
   - 如果失败，进入迭代修复环。  

> 三者由 **CrewAI 框架** 协调完成，有明确的角色分工和消息传递机制。

### 2. 迭代优化机制（Iterative Refinement Loop）

- 当 Verifier 检测到测试未全部通过时：
  1. 错误日志被送入 **Failure Abstraction Layer (FAL)**；
  2. FAL 将原始日志解析→分类→结构化成诊断信息；
  3. Editor 根据诊断对应修改，重新提交版本；
  4. 最多迭代三轮，优化通过率与计算代价的平衡。

### 3. 故障抽象层（FAL）

- **目的**：将嘈杂的测试输出转化为可执行的修复信号。  
- **三步流程**：
  1. **解析（Parsing）**：提取失败测试名、异常类型、实际与期望值。  
  2. **分类（Classification）**：归入 14 种错误类别（如断言错误、导入错误、类型错误等）。  
  3. **解释（Explanation）**：生成包含诊断、建议操作、置信度的结构化报告。  
- **优势**：无需再调用 LLM，使用确定性匹配规则，节省算力且结果可复现。  

### 4. 自动化错误分类（Error Taxonomy）

在分析任务失败原因时，引入了四类错误根源：
- **IH（Instruction Hallucination）**：误解或忽略指令。  
- **IG（Implementation Gap）**：逻辑实现错误。  
- **RE（Regression Error）**：引入新错误破坏原功能。  
- **CM（Context Misalignment）**：未正确传播修改至相关代码。

## 六、主要结论与发现

1. **总体性能提升**  
   - SAFEdit TSR 平均 **68.6%**，

     - 超出 ReAct 单智能体 (+8.6pp)。  
   - 是首个跨越 60% 门槛的多语言多任务模型框架。  

2. **迭代修正的显著作用**  
   - 首次尝试平均成功率仅约 51%，  
   - 迭代带来平均 **+17.4pp 提升**。  
   - 平均 1.8 次迭代即可收敛。  

3. **语言与上下文鲁棒性**  
   - 英语在三种可见性下表现一致（70.5% TSR）；  
   - 非英语略有波动，但整体稳定；  
   - 说明结构化规划降低了对上下文形式的依赖。  

4. **错误分析发现**  
   - SAFEdit 将错误从“Regression Error”完全消除（0%）。  
   - 指令幻觉（IH）显著减少，说明结构化分工带来更高可控性。  
   - 出错重心转为实现性差距（IG），即“已理解但未完全实现”。
