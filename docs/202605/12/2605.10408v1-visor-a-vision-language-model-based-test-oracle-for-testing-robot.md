## 摘要
测试机器人需要评估它们是否能够正确、可靠并高质量地完成预期任务，这在软件测试中被称为测试判定问题（test oracle problem）。传统上，这种评估依赖于针对特定任务的符号判定器（symbolic oracles）来判断任务是否正确，以及人工对机器人行为进行评估，这既耗时，又具有主观性且容易出错。为解决这一问题，我们提出了 VISOR——一种基于视觉语言模型（Vision-Language Model, VLM）的自动化测试判定方法，用以消除昂贵的人类评估需求。VISOR 可自动评估任务的正确性和质量，克服现有符号判定器的局限性，这些符号判定器通常只针对特定任务，且仅给出通过/未通过的判断，而不明确量化任务质量。考虑到 VLM 的固有不确定性，VISOR 还能在测试评估过程中显式量化自身的不确定性。我们使用两种 VLM（GPT 和 Gemini）在四个机器人任务、超过一千个视频上评估了 VISOR 的表现。结果显示，Gemini 的召回率更高，而 GPT 的精度更高。然而，两种模型的不确定性与正确性之间的相关性较低，这使得无法将不确定性用作正确性的预测指标。

## Abstract
Testing robots requires assessing whether they perform their intended tasks correctly, dependably, and with high quality, a challenge known as the test oracle problem in software testing. Traditionally, this assessment relies on task-specific symbolic oracles for task correctness and on human manual evaluation of robot behavior, which is time-consuming, subjective, and error-prone. To address this, we propose VISOR, a Vision-Language Model (VLM)-based approach for automated test oracle assessment that eliminates the need of expensive human evaluations. VISOR performs automated evaluation of task correctness and quality, addressing the limitations of existing symbolic test oracles, which are task-specific and provide pass/fail judgments without explicitly quantifying task quality. Given the inherent uncertainty in VLMs, VISOR also explicitly quantifies its own uncertainty during test assessments. We evaluated VISOR using two VLMs, i.e., GPT and Gemini, across four robotic tasks on over 1,000 videos. Results show that Gemini achieves higher recall while GPT achieves higher precision. However, both models show low correlation between uncertainty and correctness, which prevents using uncertainty as a correctness predictor.

## 一、研究背景与核心问题

### 研究动机
- **核心问题**：如何自动评估机器人任务的“正确性”和“质量”，即解决软件测试领域的 *test oracle problem*。
- **现实困境**：
  - 传统测试依赖人工观察或符号判定器（Symbolic Oracles）。
  - 符号判定器通常只支持特定任务，仅输出 “通过/未通过”，无法量化质量。
  - 人工评估主观性强、耗时长、难以扩展。
- **研究目标**：通过视觉语言模型（Vision-Language Model, VLM），让模型像人类一样理解任务视频并自动判断执行结果，从而替代人工判定。

## 二、研究方法：VISOR 框架与核心思想

### 核心思想
- **VISOR（Vision-Language Model-based Test Oracle）**：利用 VLM 自动分析机器人任务视频，判断执行是否成功并给出质量等级。
- **创新点**：不仅输出任务正确与否，还评估执行质量（高、中、低），同时对模型预测的不确定性进行显式量化。

### 方法流程
1. **输入数据**：机器人执行任务的视频序列，由模拟器生成，包含物体初始位置、旋转、模型ID及任务指令（如“Pick up the orange”）。
2. **VLM评估**：
   - 使用 VLM（GPT 或 Gemini）对视频帧逐序分析，输出 **任务正确性** 与 **质量等级**。
   - **正确性判定**：输出 “Success” 或 “Failure”。
   - **质量评估**：输出 “High / Medium / Low”。
3. **提示设计（Prompting）**：
   - 采用 **零样本（Zero-shot prompting）** 策略，以降低计算成本。
   - 每个任务拥有独立的提示模板，固定输出 JSON 格式结果。
4. **不确定性量化**：
   - 利用三种指标衡量模型信心：
     - **Entropy（熵）**
     - **Maximum Softmax Probability (MSP)**
     - **DeepGini**
   - 用于评估模型的结果可靠性。
5. **距离指标（Distance Metric）**：
   - 定义自有评估公式：
     - 任务正确性偏差 \(d_c\)：预测与真实一致则 0，否则 2；
     - 质量偏差 \(d_q = | \hat{q} - q |\)，其中质量等级映射为 {Failure=0, Low=1, Medium=2, High=3}；
     - 最终距离 \(d = d_c + d_q\)，范围 0–5，越低越好。

## 六、主要结论与发现

1. **任务正确性评估**：
   - Gemini：**召回率高**（更能捕获成功案例），但假阳率较高。
   - GPT：**精度高**（判断更准确），但召回率低（遗漏部分成功视频）。
   - 二者结合可互补。
2. **任务质量评估**：
   - 整体指标较低（F1 ≤ 0.48），表明多分类难度大。
   - GPT 在结果距离上更接近真值。
   - 模型普遍对微小质量差异（高/中/低）难以精准判断。
3. **不确定性分析**：
   - 两模型在所有任务上不确定性均极低，表现高度稳定。
   - 但“低不确定性”并非意味着正确——存在过度自信现象。
4. **不确定性与正确性的相关性（RQ3）**：
   - Gemini 的不确定性与预测误差呈弱正相关；
   - GPT 的相关性更弱，说明不确定性不足以预测正确性。

## 七、方法与实验优点

- **自动化评估**：无需人类介入评审视频，大幅降低成本。
- **框架通用性**：适用于多种任务，无需特定阈值调整。
- **双维度判定**：同时考虑“正确性”与“质量”，而非传统的二值判断。
- **统计完备性**：系统采用严格统计检验与多次重复，保证结果稳定。
- **显式不确定性度量**：相比传统模型，可为每次评估提供置信度信号。
- **扩展潜力**：提示设计（prompt engineering）与多模型投票可进一步增强可靠性。

## 八、不足与局限

- **任务范围有限**：仅包含四种操作，均为机器人手臂的“操作类任务”。
- **评估场景单一**：仅在模拟环境视频上测试，可能无法泛化至物理噪声、摄影抖动等真实场景。
- **模型选择限制**：仅采用两个专有模型（GPT 与 Gemini），未系统分析开源模型可调优的潜力。
- **质量分类困难**：在多分类下表现较弱，表明 VLM 对细微视觉差异的理解仍不成熟。
- **不确定性过度自信**：现有度量（Entropy、MSP、DeepGini）无法区分错误但自信的预测。
- **成本可行但实际适应性待验证**：虽然低成本，但在实时系统中仍受推理延迟限制。
