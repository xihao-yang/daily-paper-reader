## 摘要
大型语言模型（LLMs）在代码生成任务中表现出色，但其输出缺乏正确性保证。基于采样的不确定性估计器试图通过生成多个候选程序并衡量它们之间的分歧来解决这一问题。然而，现有估计器在行为的识别、聚合、参考和比较等设计选择上存在差异，使得它们难以直接评估。因此，我们首先提出了一个分类体系，以理清这些设计选择，并揭示了一个被忽视的设计点：考虑语义距离的不确定性估计方法。该方法不仅衡量采样程序是否存在分歧，还评估它们在执行行为上的差异程度。基于 LiveCodeBench、MBPP、HumanEval-X 和 BigCodeBench 的实验（涵盖 Python、Java 和 C++），我们的指标能够很好地代理正确性评估，并在封闭源模型（GPT-3.5-Turbo、GPT-4o-mini、Gemini-2.5-Flash-Lite、Claude Opus 4.5）和开源模型（DeepSeek-Coder-V2）上均显著优于最新的基于采样的基线方法。该方法具有实用性：无需访问模型内部或调用 LLM 评判，且在不同模型、编程语言、采样温度及模糊测试设置下均保持稳健，相较于现有基线，运行时间减少约 48–79%。

## Abstract
LLMs show strong performance in code generation, but their outputs lack correctness guarantees. Sample-based uncertainty estimators address this by generating multiple candidate programs and measuring their disagreement. However, existing estimators make different design choices about how behaviours are identified, aggregated, referenced and compared, making them difficult to assess. We therefore first introduce a taxonomy that disentangles these choices and reveals a missing design point: semantic distance-aware uncertainty estimation, which measures not only whether sampled programs disagree, but how severely their execution behaviours differ. Across LiveCodeBench, MBPP, HumanEval-X and BigCodeBench, spanning Python, Java and C++, our metrics provide strong proxies for correctness, and consistently outperform state-of-the-art sample-based baselines across both closed-source models (GPT-3.5-Turbo, GPT-4o-mini, Gemini-2.5-Flash-Lite, Claude Opus 4.5) and an open-source model (DeepSeek-Coder-V2). The method is practical: it requires neither model internals nor LLM-as-judge calls, remains robust across models, languages, sampling temperatures and fuzzing settings, and reduces runtime by approximately 48-79% relative to existing baselines.

## 二、方法论与核心思想

### 1. 总体思路  
作者提出基于**执行语义距离（semantic distance）**的不确定性度量框架，通过比较多个生成候选程序在相同输入下的执行结果来量化它们之间的行为差异，从而估计模型预测的不确定性大小。  
不同于过去基于二值分歧（agree/disagree）的指标，新方法采用**分级（graded）语义距离**，可捕捉代码执行的细微差异。

### 2. 四轴分类体系（理论贡献）  
作者首先建立了一个对比性框架，按四个维度对现有样本式不确定性估计方法分类：
- **等价代理（Equivalence Proxy）**：如字符串匹配、语义嵌入、符号执行、执行结果聚类等；
- **聚合结构（Aggregation）**：分为边际（marginal）或成对（pairwise）；
- **参考行为（Reference Behavior）**：比较方式为全对比（uniform-pairwise）、顶点锚定（top-anchored）、或仅主样本比较；
- **差异衡量（Dissimilarity）**：基于二值或连续距离。  
作者指出当前研究缺乏**“成对 + 分级距离”**的组合，即语义距离感知的不确定性估计。

### 3. 语义距离感知指标  
在此基础上，本文推出两个具体指标：
- **语义距离熵（Semantic Distance Entropy, SDE）**  
  - 基于 Rao’s Quadratic Entropy；
  - 通过所有行为簇之间的概率乘积与语义距离的加权和，衡量全局行为多样性；
  - 适合分析任务级或模型级不确定性。
- **主导语义距离熵（Dominant SDE, DSDE）**  
  - 仅关注包含**模型 Top-1 输出**的簇，与其他簇的语义差异；
  - 衡量模型实际展示给用户的输出的可靠性。  

公式（简化描述）：  
- 对任意脚本集合 Π，执行于共享输入集 I，基于模糊测试生成的执行签名聚类为 {C₁, …, CM}；
- 定义语义距离：  
  \(d_{ij} = \frac{1}{N}\sum_k δ(o_k(π_i), o_k(π_j))\)，  
  其中 δ 为分级代价函数（正常输出相等为0，完全不同为1，异常情况设置不同权重 a,b,c）。
- 则  
  **SDE = Σ₍i<j₎ pᵢpⱼdᵢⱼ**,  
  **DSDE = Σ₍i≠c*₎ pᵢd_{c*,i}**，   
  其中 c* 为包含 Top-1 样本的簇。

### 4. 实现流程与系统管线  
论文提出了一个端到端的“执行驱动”估计管线：
1. **采样多个候选程序 π₁…πK**；  
2. **模糊输入生成（fuzzing）**：基于类型感知的输入变异；  
3. **程序执行与簇划分**：基于执行输出相同的程序归为一类；  
4. **计算语义距离矩阵与聚合指标（SDE / DSDE）**。  
该方法无需访问模型权重、梯度或外部判别器（LLM-as-judge）。

## 三、实验设计

### 1. 使用的基准数据集与任务范围  
涵盖四个国际主流代码生成评测集：
- **LiveCodeBench (LCB)** – Python，主基准；
- **MBPP** – 简单 Python 函数级任务；
- **HumanEval-X** – Python、Java、C++；
- **BigCodeBench** – 仓库级复杂代码任务。

### 2. 对比方法与基线
与三类典型不确定性估计基线对比：
- **DiffTrust (AAAI 2026)** – 模糊执行一致性；
- **HonestCoder (2024)** – 结合语义嵌入与数据流；
- **Semantic Entropy (Nature 2024)** –基于 LLM 判断的语义聚簇熵。

### 3. 模型与参数配置
- 闭源模型：GPT-3.5-Turbo、GPT-4o-mini、Gemini-2.5-Flash-Lite、Claude Opus 4.5；  
- 开源模型：DeepSeek-Coder-V2。  
- 采样温度 T = 0.6，候选数 K = 10，模糊输入数量 N = 10。  
- 固定执行超时 0.2 秒，异常代价参数 (a,b,c) = (1,0.8,0.6)。

### 4. 评估指标
- **pass@1**（是否完全正确）；
- **partial_pass@1**（部分正确性比例）；
- **AUROC、Pearson r 与 Spearman ρ**（分别评估分类与相关性）。

## 八、不足与局限

- **依赖模糊测试输入质量：** 若输入缺乏多样性或未触及关键路径，语义等价聚类会偏粗，影响估计精度；  
- **非正确性判定器：** 语义距离无法保证与实际正确性完全一致，可能漏检多样等价实现；  
- **超参数敏感性：** 异常执行距离参数 (a,b,c) 需按语言环境细调；  
- **Top-1 锚定问题：** 当模型第一输出偏离主行为分布时，DSDE 稳定性下降；  
- **复杂任务适配性：** 在 BigCodeBench 这类多文件任务中需改用白盒模糊策略，性能有所下降。
