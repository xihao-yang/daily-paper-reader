## 摘要
近期的大规模语言模型（LLMs）在多个标准基准上表现出了卓越的自动程序修复性能。然而，这些基准仅在单一的规范化错误代码上对模型进行评估，并未反映真实世界软件中常见的语法变体，从而使得鲁棒性问题基本未被探讨。在本研究中，我们构建了 HEJ-Robust——一个基于 HumanEval-Java-Bug 并通过八种语义保持的代码变换生成的鲁棒性基准，共包含 1,450 个变换实例。我们在该基准上评估了五种经过微调的 LLM，并发现模型在若干变换下性能下降超过 50%，这表明当前基于 LLM 的程序修复模型对于轻微的语法变动缺乏鲁棒性。

## Abstract
Recent Large Language Models (LLMs) have shown strong performance on automated program repair across standard benchmarks. However, these benchmarks evaluate models on a single canonical form of buggy code and do not reflect the syntactic variations commonly observed in real-world software, leaving robustness largely unexamined. In this work, we construct HEJ-Robust, a robustness benchmark built from HumanEval-Java-Bug using eight semantics-preserving code transformations, resulting in 1,450 transformed instances. We evaluate five fine-tuned LLMs on this benchmark and show that model performance drops by over 50% under several transformations, indicating that current LLM-based repair models lack robustness to minor syntactic variations.

## 一、研究核心问题与整体含义

- **背景与动机：**
  - 自动程序修复（Automated Program Repair, APR）旨在通过生成补丁来自动修复有缺陷的代码。
  - 传统 APR 系统（如 GenProg、PAR）采用“生成—验证”范式，但存在扩展性不足与过拟合问题。
  - 近年来，大型语言模型（LLMs）如 PLBART、CodeT5 被用于代码修复任务中，并在标准基准（如 Defects4J、HumanEval-Java-Bug）上表现优异。
- **核心问题：**
  - 现有评测基准通常使用**单一“规范形式”（canonical form）的错误代码**，缺乏语法多样性。
  - 现实软件开发中广泛存在**语义等价但语法不同的代码变体**，而这些变体可能导致 LLM 输出不一致。
  - 因此，缺乏评价 LLM 修复模型在语法变体下鲁棒性的系统基准。
- **研究意义：**
  - 作者提出 **HEJ-Robust**，首次针对函数级（function-level）人造错误数据，系统评估 LLM 程序修复模型在语义保持的语法变换下的鲁棒性。

## 二、方法论：核心思想与技术细节

- **总体思路：**
  - 基于 HumanEval-Java-Bug 数据集，通过引入 8 种语义等价的代码转换，生成新的测试实例，从而构建一个鲁棒性评估基准。
  - 衡量 LLM 模型对这些细微语法变化的敏感性。
  
- **八种语义保持转换（Semantics-preserving transformations）：**
  1. **局部变量重命名**（Local Variable Renaming）
  2. **方法名重命名**（Method Renaming）
  3. **参数名重命名**（Parameter Renaming）
  4. **布尔表达式反转**（Boolean Exchange）
  5. **循环结构互换**（Loop Exchange）
  6. **条件表达式重排序**（Condition Reordering）
  7. **插入日志语句**（Insert Log Statement）
  8. **插入异常捕获**（Insert Try-Catch）

- **变换实现细节：**
  - **重命名类变换**使用 *自然化命名策略（Naturalness-aware substitution）*，利用 CodeBERT 与 GraphCodeBERT 生成上下文自然的变量名，避免噪声。
  - **结构性变换**（如循环、条件、try-catch）通过 JavaParser 与 JavaTransformer 构建 AST 修改，并验证语法有效性。
  - 转换后共得到 **1,450 个实例**，并由人工重新标注错误行位置。
  - 移除转换影响错误行的样本以保证结果有效性。

- **评估指标与任务定义：**
  - 功能正确性指标：**Pass@10**（若10个候选修复中有一个通过全部测试即判为成功）。
  - 代码相似性指标：**CodeBLEU**（仅作为对照指标）。
  - 以执行结果而非文本相似性作为主要评估标准，强调“功能鲁棒性”。

## 六、主要结论与发现

- **总体结果：**
  - 在多数变换下，5 个模型的 **Pass@10 性能均显著下降**。
  - 最大性能下降出现在 **变量重命名（Local Variable Renaming）**：
    - 降幅达 **50%–57%**。
  - 适度降幅出现在循环结构和条件重排等变换中。
  - 较小影响的情况包括参数名重命名、插入日志语句。
- **鲁棒性特征分析：**
  - 大模型并非更稳健，**模型规模与鲁棒性无明显正相关**（例如 CodeT5-large 在多处表现不如 base 版）。
  - CodeBLEU 对性能变化不敏感，说明语法级相似性指标难以反映功能差异。
- **结论：**
  - 现有 LLM 修复模型在轻微语法变化下普遍脆弱。
  - Pass@10 明显优于 CodeBLEU，可更准确地反映功能鲁棒性。
  - HEJ-Robust 可为未来鲁棒性评估、对抗训练和稳健性优化提供研究基础。
