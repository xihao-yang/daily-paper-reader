## 摘要
基于强化学习的程序修复受到稀疏的执行反馈和粗粒度序列级奖励的限制，这种设置模糊了哪些编辑真正修复了错误。我们提出了 BoostAPR，这是一种三阶段框架，用以应对这些挑战：（1）在带有推理轨迹的执行验证示例上进行有监督微调；（2）基于执行结果训练双重奖励模型——序列级评估器与行级信用分配器；（3）采用 PPO 优化，其中行级模型将奖励重新分配到关键编辑区域。行级信用分配在中间粒度上运作，自然契合于代码修改任务。在 SWE-Gym 上进行训练，并在四个基准上进行评测，BoostAPR 在 SWE-bench Verified 上达到 40.7%（较基线模型提高 22.9 个百分点），在 Defects4J（Python 到 Java 迁移）上达到 24.8%，在 HumanEval-Java 上达到 84.5%，在 QuixBugs 上达到 95.0%，在开源模型中实现了具有竞争力的性能，并展现出较强的跨语言泛化能力。

## Abstract
Reinforcement learning for program repair is hindered by sparse execution feedback and coarse sequence-level rewards that obscure which edits actually fix bugs. We present BoostAPR, a three-stage framework addressing these challenges: (1) supervised fine-tuning on execution-verified demonstrations with reasoning traces, (2) training dual reward models--a sequence-level assessor and a line-level credit allocator--from execution outcomes, and (3) PPO optimization where the line-level model redistributes rewards to critical edit regions. This line-level credit assignment operates at an intermediate granularity naturally suited to code changes. Trained on SWE-Gym and evaluated on four benchmarks, BoostAPR achieves 40.7% on SWE-bench Verified (+22.9pp over base model), 24.8% on Defects4J (Python-to-Java transfer), 84.5% on HumanEval-Java, and 95.0% on QuixBugs, achieving competitive results among open-source models with strong cross-language generalization.

## 一、研究问题与背景

- **核心问题**：自动化程序修复（Automated Program Repair, APR）旨在自动为含有缺陷的软件代码生成正确补丁。随着大语言模型（LLM）的发展，模型已能生成带上下文的补丁，但强化学习（RL）在该任务中的表现仍受三类主要挑战限制：  
  1. **执行反馈稀疏**：程序修复的反馈通常只有“通过/失败”二值信号，无法部分奖励接近正确的修改。  
  2. **奖励粒度过粗**：奖励常分配在序列级别，难以确定具体哪一行修改导致修复成功或失败。  
  3. **分布偏移与泛化问题**：训练集与实际软件中的错误类型差异大，导致模型在真实项目中的表现下降。

- **研究动机**：提升强化学习的奖励分配与收敛效率，使其能够从执行验证结果中学习并在不同代码语言与项目间保持泛化性。

## 二、方法论与技术框架

### 核心思想

论文提出 **BoostAPR**，一个 **三阶段执行驱动的强化学习框架**，用以缓解奖励稀疏与信用分配问题。它通过引入两个互补的奖励模型，在执行反馈的基础上实现细粒度信用分配。

### 三阶段方法结构

1. **阶段 I：执行验证的有监督微调（SFT）**
   - 在 SWE-Gym 数据集上筛选通过完整测试集的高质量修复示例。
   - 教师模型（Claude 3.5 Sonnet）生成包含“推理轨迹 + 补丁”的训练数据。
   - 学生模型采用 Qwen2.5-Coder-32B，为后续强化学习打基础。  
   - 训练目标：标准交叉熵损失（next-token prediction）。

2. **阶段 II：双重奖励模型训练（Dual Reward Models）**
   - **Rseq（序列级评估器）**：仅根据补丁（unified diff）预测整体质量，避免依赖上下文偏差。
     - 混合目标：回归损失 + 成对偏好损失，确保绝对值校准与相对排序稳定。
   - **Rline（行级信用分配器）**：针对具体编辑行分配奖励权重，通过堆栈跟踪确定哪些行导致失败或成功。
     - 监督信号源自执行反馈的堆栈追踪（stack-trace attribution），避免昂贵的反事实实验。

3. **阶段 III：基于 PPO 的在线强化学习优化**
   - 使用 **Proximal Policy Optimization (PPO)** 进行参数高效训练（LoRA rank=64）。  
   - 奖励分配：
     - Rseq 提供总体分数；
     - Rline 以 softmax 加权分配至每行 token；
     - 加入统一 diff 格式惩罚项以约束输出合法性。
   - 理论上，行级奖励分配能显著降低梯度方差，提高训练稳定性。

### 算法流程（文字版）

Algorithm 1 概述如下：

1. 从教师生成执行验证样本并进行 SFT；
2. 采样候选补丁并执行测试以生成奖励数据；
3. 训练 Rseq 与 Rline 模型；
4. 在 PPO 中使用二者联合计算 token-level reward；
5. 迭代更新策略直至收敛，输出最终修复模型。

## 六、主要结论与发现

- **性能提升**：
  - SWE-bench Verified：提高 22.9 个百分点（40.7%）。
  - Defects4J：提高 13.5个百分点（24.8%）。
  - HumanEval-Java：提高 20.5个百分点（84.5%）。  
  - QuixBugs：达 95.0%，逼近满分。

- **贡献分解**：
  - 增益中 65% 来自 PPO + Rseq，行级分配器 Rline 提供额外稳定性与跨语言泛化。

- **理论结论**：
  - 行级奖励能将梯度方差从 O(T·Var[R]) 降低至 O(k·Var[R])（T 为序列长度，k 为有效编辑行数），加速收敛。
  - Rline 提供的中间粒度信用分配在代码编辑中既稳定又语言无关。

## 八、不足与局限

- **奖励监督噪声**：行级标签部分依赖堆栈追踪和启发式规则，准确性有限（约70–80%一致率）。
- **语义粒度近似**：“行”并不总对应真正的语义单元，在跨语言或多文件修复中仍有偏差。
- **对比受限**：论文未与工业级闭源系统（如 GPT-4）做直接性能比较，仅报告上下文参考。
- **任务边界**：主要聚焦单次补丁生成，未涉及持续迭代或交互式修复场景。
- **消融偏重于代码层面**：尚未探讨奖励模型的稳定性在大规模 RLHF 或多任务环境中的迁移。
