## 摘要
强化学习在程序修复中的应用受到稀疏的执行反馈以及粗粒度的序列级奖励的限制，这些奖励难以揭示哪些编辑真正修复了错误。我们提出 BoostAPR，一个三阶段框架以应对这些挑战：（1）在具有推理轨迹的执行验证示范上进行有监督微调；（2）基于执行结果训练双重奖励模型——序列级评估器和行级信用分配器；（3）在 PPO 优化中，由行级模型将奖励重新分配给关键编辑区域。该行级信用分配在适合代码变更的中间粒度上运行。我们在 SWE-Gym 上训练模型，并在四个基准上进行评测：BoostAPR 在 SWE-bench Verified 上达到 40.7%（比基线模型提升 22.9 个百分点），在 Defects4J（Python 到 Java 迁移）上为 24.8%，在 HumanEval-Java 上为 84.5%，在 QuixBugs 上为 95.0%，在开源模型中表现出具有竞争力的结果及强大的跨语言泛化能力。

## Abstract
Reinforcement learning for program repair is hindered by sparse execution feedback and coarse sequence-level rewards that obscure which edits actually fix bugs. We present BoostAPR, a three-stage framework addressing these challenges: (1) supervised fine-tuning on execution-verified demonstrations with reasoning traces, (2) training dual reward models--a sequence-level assessor and a line-level credit allocator--from execution outcomes, and (3) PPO optimization where the line-level model redistributes rewards to critical edit regions. This line-level credit assignment operates at an intermediate granularity naturally suited to code changes. Trained on SWE-Gym and evaluated on four benchmarks, BoostAPR achieves 40.7% on SWE-bench Verified (+22.9pp over base model), 24.8% on Defects4J (Python-to-Java transfer), 84.5% on HumanEval-Java, and 95.0% on QuixBugs, achieving competitive results among open-source models with strong cross-language generalization.

## 一、核心问题与研究动机

- **研究背景**：自动程序修复（Automated Program Repair, APR）是软件工程中旨在自动生成代码补丁，以修复程序错误的关键问题。该领域传统方法依赖静态分析和启发式搜索，但难以在真实复杂代码环境中高效表现。
- **面临瓶颈**：基于大型语言模型（LLMs）的程序修复虽然取得进展，但强化学习（RL）在此任务中仍受限于以下问题：
  1. **稀疏的执行反馈**：模型只能获得“是否通过所有测试”的二值信号，缺乏中间奖励。
  2. **粗粒度的序列级奖励**：系统仅对完整补丁给出整体好坏评价，无法识别哪些具体修改贡献最大。
  3. **数据分布偏移**：训练数据与真实仓库中的缺陷分布差异较大，影响泛化性能。
- **研究目标**：BoostAPR 希望通过执行落地的强化学习（execution-grounded RL）与精细化奖励分配，提升模型学习效率和修复准确率，尤其在跨语言与复杂仓库任务中。

## 二、方法论：三阶段框架与关键技术

### 1. 总体思路
BoostAPR 构建了一个 **三阶段执行驱动学习框架**，从监督学习到强化学习逐步提升模型的修复能力：
- **阶段 I — 执行验证的监督微调（SFT）**：在通过执行验证的高质量示范上学习，包括推理轨迹（reasoning trace）和有效补丁。
- **阶段 II — 双重奖励模型训练**：从执行反馈中学习两个奖励模型：
  - **序列级评估器 (Rseq)**：预测整体补丁质量。
  - **行级信用分配器 (Rline)**：识别关键编辑行，为奖励分配提供精细化权重。
- **阶段 III — 基于 PPO 的在线强化优化**：使用 Proximal Policy Optimization (PPO)，结合行级权重生成令牌级奖励，实现稳定高效的策略更新。

### 2. 关键算法与原理说明

- **奖励生成公式**：  
  \( r^*(x,y) = r_{env}(x,y) + \gamma_{diff}·r_{diff}(y) \)  
  其中 \(r_{env}\) 综合补丁应用成功与测试通过率，\(r_{diff}\) 对过大修改进行惩罚。
  
- **双奖励模型训练目标**：
  - Rseq 采用**混合目标函数**（回归 + 对比）：
    \[
    L_{seq} = λ_{reg}·E[(R_{seq}(y)-r^*)^2] + E[-w·logσ(R_{seq}(y^+) - R_{seq}(y^-))]
    \]
    以同时保持数值稳定与相对排序正确。
  - Rline 通过对比学习训练：
    \[
    L_{line} = E[-logσ(R_{line}(ℓ^+) - R_{line}(ℓ^-))]
    \]
    其中正负样本来自执行期间的堆栈追踪与错误行标注。

- **奖励分配机制**：  
  使用温度控制的 softmax 将 Rline 的行级评分转化为权重 \(w_ℓ\)，再将整体奖励分配给行内令牌，实现语义层次的信用分配。

- **优化过程（PPO）**：
  - 使用标准 PPO 损失：
    \[
    J_{clip}(θ) = E[min(ρ_tA_t, clip(ρ_t,1−ϵ,1+ϵ)A_t)]
    \]
  - 加入 KL 惩罚项和格式惩罚保障补丁格式正确性。

## 八、不足与局限

- **奖励监督噪声**：行级奖励的堆栈追踪标注存在启发式噪声（约 30%为函数级推断）。
- **粒度选择近似**：行级分配未必总与语义边界对齐，可能对结构变化的补丁不够精确。
- **规模限制**：采用 32B backbone，虽控制公平，但与70B模型比较受限。
- **长序列与多文件修复挑战**：当前Patch仅针对单文件，不覆盖跨文件依赖。
- **评测范围有限**：尽管有多benchmark，但未包含真实企业级仓库或C/C++任务。
- **潜在风险**：模型可能生成“测试通过但语义错误”的补丁。
