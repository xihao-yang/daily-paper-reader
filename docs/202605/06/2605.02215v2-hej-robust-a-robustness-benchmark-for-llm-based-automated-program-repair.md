## 摘要
近年来，大型语言模型（LLMs）在标准基准上的自动程序修复任务中表现出强劲性能。然而，这些基准仅在单一规范形式的错误代码上评估模型，并未反映真实世界软件中常见的语法变异，从而使模型鲁棒性几乎未被检验。在本研究中，我们构建了 HEJ-Robust，这是一项基于 HumanEval-Java-Bug 的鲁棒性基准，通过八种保持语义不变的代码转换生成，共得到 1,450 个转换实例。我们在该基准上评估了五种经微调的 LLM，结果显示模型在若干转换下性能下降超过 50%，这表明当前基于 LLM 的自动修复模型对轻微语法变异的鲁棒性不足。

## Abstract
Recent Large Language Models (LLMs) have shown strong performance on automated program repair across standard benchmarks. However, these benchmarks evaluate models on a single canonical form of buggy code and do not reflect the syntactic variations commonly observed in real-world software, leaving robustness largely unexamined. In this work, we construct HEJ-Robust, a robustness benchmark built from HumanEval-Java-Bug using eight semantics-preserving code transformations, resulting in 1,450 transformed instances. We evaluate five fine-tuned LLMs on this benchmark and show that model performance drops by over 50% under several transformations, indicating that current LLM-based repair models lack robustness to minor syntactic variations.

## 2. 方法论：核心思路与技术方案  

### 2.1 基本思想  
通过对原有的 **HumanEval-Java-Bug** 数据集施加八种“语义保持（semantics-preserving）”的代码变换，构建一组语法上不同但功能等价的修复测试集，用以度量 LLM 修复模型的**稳健性（robustness）**。

### 2.2 八种语义保持的代码变换  

| 类型 | 描述 | 示例效果 |
|------|------|-----------|
| Local Variable Renaming | 局部变量重命名 | `int temp=0; → int count=0;` |
| Method Renaming | 方法名重命名 | `compute() → calculate()` |
| Parameter Renaming | 参数名重命名 | `void foo(int x) → void foo(int val)` |
| Log Statement Insertion | 添加打印语句（不影响语义） | 增加 `System.out.println("log");` |
| Try–Catch Insertion | 添加空异常捕获块 | 包裹调用语句为 `try–catch` |
| Boolean Exchange | 改变布尔初值并取反使用 | `boolean res=true; → false; return !res;` |
| Loop Exchange | 语法等价的 `for` 与 `while` 互换 | `for` ↔ `while` |
| Condition Reordering | 条件表达式左右操作数互换 | `if(a==b) → if(b==a)` |

### 2.3 技术实现细节  

- **语义保持保证：** 使用 AST 解析（JavaParser + Tree-sitter），确保代码修改在语法上合法且逻辑等价。  
- **自然化命名策略：** 对重命名操作，使用 CodeBERT 与 GraphCodeBERT 生成上下文相关、自然的命名候选，选择最相近的嵌入向量（cosine similarity），避免“随机命名”导致的数据分布偏差。  
- **手动再标注：** 由于变换可能改变 bug 行位置，作者手动重新标注每个实例的错误行，并交叉验证 10% 样本以确保一致性。  
- **评估指标：**  
  - **Pass@10**：生成 10 个修复候选，只要有一个通过所有测试即计为成功。  
  - **CodeBLEU**：辅助代码相似度指标（但论文证明其对功能鲁棒性不敏感）。

## 6. 主要结论与发现  

- **核心结论：** 当前 LLM 程序修复模型对轻微的语法变化高度敏感。  
- **主要实验结果：**
  - 在 **局部变量重命名** 下，Pass@10 降幅高达 **50–57%**。  
  - **循环结构变换**、**条件重排序** 导致中度下降（约 5–15%）。  
  - **方法名**与**参数名**重命名、**日志插入**影响较小或偶有正向波动。  
  - **模型大小与鲁棒性无必然正相关**（大模型在多项变换下反而更弱）。  
  - **CodeBLEU 指标**几乎不变，说明字符串相似度无法反映功能鲁棒性，应采用执行级指标（Pass@k）。
