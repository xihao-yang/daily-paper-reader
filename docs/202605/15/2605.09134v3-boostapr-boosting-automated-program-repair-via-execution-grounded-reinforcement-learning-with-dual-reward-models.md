## 摘要
基于强化学习的程序修复受到稀疏的执行反馈和粗粒度的序列级奖励的限制，使得真正修复漏洞的编辑难以识别。我们提出了 BoostAPR，一个针对这些挑战的三阶段框架：（1）在带有推理轨迹的、经执行验证的示范数据上进行监督微调；（2）基于执行结果训练双奖励模型——包括序列级评估器和行级奖励分配器；（3）通过 PPO 优化，其中行级模型将奖励重新分配至关键编辑区域。该行级信用分配机制在自然适用于代码修改的中间粒度上运行。我们在 SWE-Gym 上进行训练，并在四个基准测试上评估，BoostAPR 在 SWE-bench Verified 上达到 40.7%（较基线模型提升 22.9 个百分点），在 Defects4J（Python 到 Java 迁移场景）上达到 24.8%，在 HumanEval-Java 上达到 84.5%，在 QuixBugs 上达到 95.0%，在开源模型中取得了竞争性的跨语言泛化性能。

## Abstract
Reinforcement learning for program repair is hindered by sparse execution feedback and coarse sequence-level rewards that obscure which edits actually fix bugs. We present BoostAPR, a three-stage framework addressing these challenges: (1) supervised fine-tuning on execution-verified demonstrations with reasoning traces, (2) training dual reward models--a sequence-level assessor and a line-level credit allocator--from execution outcomes, and (3) PPO optimization where the line-level model redistributes rewards to critical edit regions. This line-level credit assignment operates at an intermediate granularity naturally suited to code changes. Trained on SWE-Gym and evaluated on four benchmarks, BoostAPR achieves 40.7% on SWE-bench Verified (+22.9pp over base model), 24.8% on Defects4J (Python-to-Java transfer), 84.5% on HumanEval-Java, and 95.0% on QuixBugs, achieving competitive results among open-source models with strong cross-language generalization.

## 一、核心问题与研究背景

- **研究动机**  
  自动程序修复（Automated Program Repair, APR）旨在自动生成能修复代码错误的补丁，是软件工程中节约维护成本与提高开发效率的关键研究方向。  
  近年来大型语言模型（LLMs）在代码生成和理解上取得显著进展，但在 APR 中应用仍面临以下挑战：
  1. **奖励信号稀疏**：修复成功与否通常是二元反馈（通过/未通过测试），难以提供中间学习信息；
  2. **奖励粒度过粗**：通常以序列级别评估补丁整体质量，无法分辨哪些具体编辑真正有助于修复；
  3. **分布差异问题**：训练与真实应用场景在代码结构与错误类型上存在分布偏移，模型泛化力不足。

- **研究目标**  
  作者旨在通过强化学习（RL）结合执行反馈和细粒度奖励机制，提高模型定位关键修复区域的能力，同时提升训练稳定性与跨语言表现。

## 二、方法论：三阶段框架

### 1. 整体架构

论文提出的 **BoostAPR** 为三阶段训练框架（见原文 Figure 1）：
1. **阶段 I：执行验证的监督微调（SFT）**
2. **阶段 II：基于执行结果的双奖励模型学习**
3. **阶段 III：使用 PPO 的在线强化学习优化**

### 2. 核心思想

- 通过执行验证过滤高质量示范，提升初始模型的修复与推理能力；
- 使用两个奖励模型分别学习：
  - **R_seq（序列级奖励模型）**：评估补丁整体质量；
  - **R_line（行级信用分配器）**：细化奖励至关键编辑行，解决“信用分配”问题；
- 将上述奖励在 PPO 中结合，实现 **自适应的行级奖励塑形（reward shaping）**。

### 3. 技术细节与算法说明

#### 阶段 I：执行验证的监督微调
- 由教师模型（Claude 3.5 Sonnet）生成“推理轨迹 + 补丁”示范；
- 仅保留通过所有测试的样本（约 35%）；
- 使用标准语言建模损失进行微调（方程式 (2)）。

#### 阶段 II：双奖励模型训练
- 收集每个训练实例的多个候选补丁（K = 4），运行测试获取执行反馈；
- 设计复合奖励函数：
  \[
  r^*(x, y) = r_{env}(x, y) + \gamma_{diff} \cdot r_{diff}(y)
  \]
  包括应用成功率、测试通过率以及补丁长度惩罚；
- **R_seq** 采用回归 + 偏好学习混合目标（方程式 (4)），确保排名正确与数值尺度稳定；
- **R_line** 从执行堆栈追踪中提取行级标注，通过对成功与失败行的对比学习（方程式 (6)）训练。

#### 阶段 III：PPO 强化学习
- 在强化学习阶段，将序列总奖励通过 R_line 分配至各编辑行，再映射到 token 级；
- 应用格式惩罚确保仅评估实际补丁部分；
- 采用标准 clipped-PPO 目标（方程式 (9)）及 KL 正则稳定训练（算法 1）。

## 八、不足与局限

- **R_line 标签噪声**：由堆栈追踪与启发式生成，准确率约 82%，仍非精确因果归因；
- **编辑粒度近似**：行级分配虽语言无关，但不总与语义边界对齐；
- **数据规模限制**：仅在 SWE-Gym 单一训练源上训练，未测试大规模跨仓库泛化；
- **大型模型比较受限**：未与更强模型（如 70B 级 Llama 背骨）在完全相同环境下比较；
- **风险提示**：自动生成补丁仍可能引入隐含错误或安全漏洞，需人工审核。
