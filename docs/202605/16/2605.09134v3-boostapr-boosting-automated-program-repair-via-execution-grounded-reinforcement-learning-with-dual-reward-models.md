## 摘要
基于强化学习的自动程序修复受到稀疏执行反馈和粗粒度序列级奖励的限制，使得难以明确哪些编辑真正修复了漏洞。我们提出了 BoostAPR，这是一种三阶段框架，用于应对这些挑战：（1）在具备推理轨迹的已验证执行示例上进行监督微调；（2）从执行结果中训练双重奖励模型——包括序列级评估器和行级奖励分配器；（3）在 PPO 优化过程中，行级模型将奖励重新分配到关键编辑区域。该行级奖励分配机制以自然适应代码更改的中间粒度运行。在 SWE-Gym 上训练并在四个基准测试中评估后，BoostAPR 在 SWE-bench Verified 上取得了 40.7% 的成绩（比基础模型提升 22.9 个百分点），在 Defects4J （Python 到 Java 迁移）上为 24.8%，在 HumanEval-Java 上为 84.5%，在 QuixBugs 上为 95.0%，在开源模型中实现了具备强跨语言泛化能力的竞争性结果。

## Abstract
Reinforcement learning for program repair is hindered by sparse execution feedback and coarse sequence-level rewards that obscure which edits actually fix bugs. We present BoostAPR, a three-stage framework addressing these challenges: (1) supervised fine-tuning on execution-verified demonstrations with reasoning traces, (2) training dual reward models--a sequence-level assessor and a line-level credit allocator--from execution outcomes, and (3) PPO optimization where the line-level model redistributes rewards to critical edit regions. This line-level credit assignment operates at an intermediate granularity naturally suited to code changes. Trained on SWE-Gym and evaluated on four benchmarks, BoostAPR achieves 40.7% on SWE-bench Verified (+22.9pp over base model), 24.8% on Defects4J (Python-to-Java transfer), 84.5% on HumanEval-Java, and 95.0% on QuixBugs, achieving competitive results among open-source models with strong cross-language generalization.

## 一、研究问题与整体背景

- **核心问题**：自动程序修复（Automated Program Repair, APR）旨在利用 AI 自动生成代码补丁以修复软件漏洞。随着大语言模型（LLM）的兴起，LLM 在程序修复领域取得了显著进展，但仍面临两个关键挑战：  
  1. **执行反馈稀疏**：一个补丁要么通过全部测试，要么完全失败，导致强化学习无法获得细粒度的学习信号。  
  2. **奖励粒度过粗**：传统 RL 仅在序列级别（整段补丁）赋予奖励，难以判定哪些编辑行真正起作用，造成梯度方差大、收敛慢。  

- **研究目标**：提出一种执行反馈驱动的强化学习框架，可以从代码的实际运行结果中学习修复策略，同时在编辑行级别分配奖励，提高学习效率与泛化能力。

## 二、方法论与技术细节

BoostAPR 的核心是一种 **三阶段框架**，包括监督学习、奖励建模和强化优化三部分。

### 1. 阶段 I：执行验证的监督微调（Execution-Verified SFT）

- 使用强教师模型（Claude 3.5 Sonnet）生成包含“推理轨迹 + 修复补丁”的示例。  
- 保留**通过全部测试**的高质量示例（约占35%），过滤掉错误或不可执行补丁。  
- 用标准的交叉熵损失进行微调，以转移诊断推理能力与修复知识（学习率 2×10⁻⁵，批次 32，训练 3 轮）。

### 2. 阶段 II：基于执行反馈的双重奖励模型（Dual Reward Models）

包括两个奖励模型：

- **序列级奖励模型 R_seq**：评估整体补丁质量，仅对补丁内容评分而不看上下文，防止偏见。  
  - 使用混合目标函数：
    - 回归项保证绝对分数可校准；
    - 偏好项确保相对排名正确。  
  - 公式：  
    L_seq = λ_reg·E[(R_seq − r*)²] + E[-w·log σ(R_seq(y⁺) − R_seq(y⁻))]

- **行级奖励分配器 R_line**：学习在补丁的编辑行间分配信用。  
  - 输入编辑行内容、上下文、文件名与位置；
  - 通过 softmax 分配权重： w_ℓ = exp(s_ℓ/τ) / Σ exp(s_j /τ)；
  - 监督来自执行失败堆栈追踪，将相关编辑行标为负样本（基于堆栈与函数级启发式标签）。

### 3. 阶段 III：基于 PPO 的在线强化优化

- 使用 **Proximal Policy Optimization (PPO)** 对模型进行在线优化。  
- **奖励整形**：将 R_seq 的序列得分按 R_line 权重分配到各 token。  
  - 每个 token 的奖励 rt = s·a_t + format penalty；  
  - 对补丁格式错误增加罚分，确保生成结构正确的 unified diff。  
- 采用标准 PPO 损失函数，含 KL 正则与 GAE 优化；训练 300 步。  
- 参数更新采用 **LoRA（rank=64）**，提高训练效率。

- **安全与可信性风险**：自动生成补丁可能修复表面错误，潜藏新漏洞。
