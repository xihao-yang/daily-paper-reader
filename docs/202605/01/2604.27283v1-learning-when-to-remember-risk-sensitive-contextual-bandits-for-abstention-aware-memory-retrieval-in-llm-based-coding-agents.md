## 摘要
基于大型语言模型（LLM）的编码代理越来越依赖外部记忆，以复用过往的调试经验、修复轨迹以及代码库内的操作知识。然而，只有当当前故障与先前故障真正兼容时，检索到的记忆才有用；堆栈跟踪、终端错误、路径或配置症状的表面相似可能导致不安全的记忆注入。本文将问题记忆的使用重新表述为一个选择性、风险敏感的控制问题，而非单纯的 top-k 检索问题。我们提出了 RSCB-MC，这是一种风险敏感的上下文多臂赌博机式记忆控制方法，用于决定代理是否应：不使用记忆、注入最佳解决方案、汇总多个候选项、执行高精度或高召回检索、放弃或请求反馈。系统通过“模式–变体–情节”架构存储可复用的问题知识，并将检索证据转换为一个包含 16 个特征的固定上下文状态，以捕捉相关性、不确定性、结构兼容性、反馈历史、假阳性风险、延迟和 token 成本。该系统的奖励设计对错误的记忆注入惩罚高于错失复用，从而将不注入和放弃视为一级安全操作。在确定性的小规模工件实验中，RSCB-MC 在非 oracle 离线回放情境下取得了 62.5% 的最高成功率，同时保持 0.0% 的假阳性率。于限制的 200 案例热路径验证中，它达到了 60.5% 的代理成功率，假阳性率为 0.0%，决策延迟（p95）为 331.466 微秒。结果表明，对于编码代理的记忆而言，关键问题不仅在于哪段记忆最相似，更在于任何被检索的记忆是否足够安全，能够影响调试过程。

## Abstract
Large language model (LLM)-based coding agents increasingly rely on external memory to reuse prior debugging experience, repair traces, and repository-local operational knowledge. However, retrieved memory is useful only when the current failure is genuinely compatible with a previous one; superficial similarity in stack traces, terminal errors, paths, or configuration symptoms can lead to unsafe memory injection. This paper reframes issue-memory use as a selective, risk-sensitive control problem rather than a pure top-k retrieval problem. We introduce RSCB-MC, a risk-sensitive contextual bandit memory controller that decides whether an agent should use no memory, inject the top resolution, summarize multiple candidates, perform high-precision or high-recall retrieval, abstain, or ask for feedback. The system stores reusable issue knowledge through a pattern-variant-episode schema and converts retrieval evidence into a fixed 16-feature contextual state capturing relevance, uncertainty, structural compatibility, feedback history, false-positive risk, latency, and token cost. Its reward design penalizes false-positive memory injection more strongly than missed reuse, making non-injection and abstention first-class safety actions. In deterministic smoke-scale artifacts, RSCB-MC obtains the strongest non-oracle offline replay success rate, 62.5%, while maintaining a 0.0% false-positive rate. In a bounded 200-case hot-path validation, it reaches 60.5% proxy success with 0.0% false positives and a 331.466 microseconds p95 decision latency. The results show that, for coding-agent memory, the key question is not only which memory is most similar, but whether any retrieved memory is safe enough to influence the debugging trajectory.

- **总体目标**：将“记忆检索”从单纯的相似度排序问题转化为一个**风险敏感的决策控制问题**，即学习“何时不应记忆”。

## 二、方法论：RSCB-MC 的核心思想与技术实现

### 1. 整体框架

- **方法名称**：RSCB-MC（Risk-Sensitive Contextual Bandit with Memory Control）
- **思想核心**：  
  将记忆使用决策形式化为**上下文多臂赌博机（Contextual Bandit）**问题，每次遇到调试错误时，控制器需在多种动作中选择安全、最优的行动。

### 2. 模型组成

- **三层记忆结构**：  
  - **Pattern（模式）**：错误类型与根因的规范表示。  
  - **Variant（变体）**：与具体仓库相关的修复方法、命令、路径、堆栈特征。  
  - **Episode（情节）**：具体失败实例及其验证/反馈记录。  
  > 此结构避免了不同根因被表面相似信息错误合并的风险。

- **16维上下文特征向量（zt ∈ ℝ16）**：  
  包含检索得分、得分熵、候选数量、失败族置信度、命令/路径/堆栈匹配率、历史拒绝次数、假阳性率、延迟与token预算等（见表1）。

- **动作空间（A）**：  
  包含 7 种可能操作：
  1. 不使用记忆（no memory）  
  2. 注入最佳候选（top1 resolution）  
  3. 汇总前3项（top3 summary）  
  4. 高精度检索（high precision retrieval）  
  5. 高召回检索（high recall retrieval）  
  6. 放弃（abstain）  
  7. 请求反馈（ask feedback）  
  > “放弃”和“不使用记忆”被定义为一级安全行为。

### 3. 奖励函数与风险建模

- 奖励公式：  
  \[
  r_t = \alpha I_{verified} + \beta I_{accepted} + \kappa I_{correct\_abstain} - \gamma I_{false\_positive} - \delta I_{rejected} - ηL_t - λT_t
  \]
  - 惩罚顺序保持 **γ > α > β**，即“错误注入”比“成功复用”的代价更大。
  - 目标是最大化期望收益同时最小化假阳性率与开销（Latency、Token成本）。

- 决策函数：基于风险正则化得分  
  \[
  S(a,z_t) = \hat{R}(a,z_t) - \mu \hat{p}_{fp}(a,z_t) - λ_c \hat{c}(a,z_t)
  \]
  并可触发安全覆盖（SafetyOverride）机制，将高风险操作自动替换为“放弃”或“不使用记忆”。

### 4. 算法流程（文字版）

1. **输入**调试上下文并标准化生成查询向量。  
2. **检索**候选记忆集 Ct。  
3. **构建状态向量 zt**（16 特征）。  
4. **计算每个动作的奖励、风险与成本**。  
5. **选择得分最高且满足安全条件的动作**。  
6. **执行动作 → 获取反馈 → 更新策略参数 Θ。**

## 六、主要结论与发现

- **核心结论**：
  - RSCB-MC 在离线复现中取得最高非 oracle 成功率 **62.5%**，假阳性率 **0%**。

  - 安全性优于检索精度：RSCB-MC 强调“是否可安全使用记忆”比“哪段记忆相似”更重要。
