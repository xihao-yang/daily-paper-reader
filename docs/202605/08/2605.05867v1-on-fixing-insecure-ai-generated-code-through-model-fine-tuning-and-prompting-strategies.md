## 摘要
AI 生成代码的安全性仍然是其广泛应用的一大障碍。尽管代码生成模型在功能性基准测试上表现出色，但其输出往往包含漏洞和安全弱点，从而削弱了可信度。先前的研究探索了多种缓解 AI 生成代码安全问题的方法，例如基于静态分析引导的生成和提示工程。然而，这些方法在不同模型和应用场景中的有效性差异很大。本文系统地研究了针对常见弱点枚举（CWE）列表中漏洞的模型生成代码加固策略。我们通过模型微调和提示策略来优化输出，以评估这些方法在不同模型和编程语言中的安全提升效果。除了分析安全弱点的普遍性外，我们还分析了检测到的 CWE 的严重程度、共现关系，以及修复带来的非预期后果（例如修复某个弱点是否会在同一代码中引入新的弱点）。研究结果表明，安全改进高度依赖于策略和模型。尽管某些方法能减少特定类别的弱点，但它们往往在修复的同时引入新的问题。此外，没有任何单一策略能在所有模型和场景下始终如一地消除弱点，这突显了在实现安全 AI 代码生成方面仍缺乏通用且“万无一失”的解决方案。

## Abstract
The security of AI-generated code remains a major obstacle to its widespread adoption. Although code generation models achieve strong performance on functional benchmarks, their outputs frequently contain bugs and security weaknesses that undermine their trustworthiness. Prior work has explored a range of approaches to mitigate security issues in AI-generated code, e.g., using static analysis-guided generation and prompt engineering. However, their effectiveness varies widely across models and settings. This paper presents a systematic investigation of strategies for hardening model-generated code against a list of Common Weakness Enumeration (CWE). We assess the extent to which these strategies improve security across models and programming languages, using fine-tuning and prompting approaches for model output refinement. Beyond the prevalence of security weaknesses, we analyse the severity of identified CWEs, their co-occurrence, and the unintended consequences of remediation (i.e., whether fixing certain weaknesses introduces new weaknesses elsewhere in the same code). Our results show that security improvements are highly strategy- and model-dependent. Although some approaches reduce specific classes of weaknesses, they often introduce new weaknesses as side effects of the fixes. Moreover, no strategy consistently eliminates weaknesses across all models and scenarios, highlighting the absence of a universally effective "bulletproof" solution for secure AI-generated code.

## 二、方法论：核心思想与技术流程

### 1. 核心理念
通过 **模型输出再优化（Model Output Refinement）** 的方式，提高 LLM 生成代码的安全性，主要分为两大类别：  
- **提示工程（Prompting-based strategies）**：修改输入提示，引导模型生成更安全的代码；  
- **模型微调（Fine-tuning-based strategies）**：在安全代码数据上继续训练模型，使其内部参数向安全行为分布靠拢。

### 2. 四种主要技术策略
| 策略名称 | 类别 | 核心机制 | 关键作用 |
|-----------|--------|------------|------------|
| Negative Example Prompting (NEP) | 提示 | 向模型展示“不安全代码”的反例，请其改进生成 | 模拟“反例学习” |
| Chain-of-Thought Prompting (CoT) | 提示 | 显式推理式提示，让模型逐步思考安全检查与编码规范 | 强化思维链条与防护逻辑 |
| Meta Prompting (MP) | 提示 | 让模型先生成用于安全编码的提示，再利用该提示生产代码 | 模型自生成提示的“元学习” |
| Fine-Tuning (LoRA) | 微调 | 使用安全代码集微调模型权重（采用 Low-Rank Adaptation） | 直接调整模型安全分布 |

### 3. 算法设计（文字化总结）
通用框架（Algorithm 1 “Full Framework”）流程：
1. 准备 10 个 CWE 场景；
2. 各模型首先生成原始（Raw）不加干预的代码；
3. 对每个初始样本，分别应用 4 个策略生成改进版本；
4. 使用静态分析工具 CodeQL 检测 CWE 并计算 CWE 严重度得分；
5. 统计各策略的漏洞减少率与严重度改善百分比。

**评价指标：**
- CWE 数量减少百分比；  
- CWE 总严重度分数下降率（基于 CVSS 3.1 75th percentile 规则）。

公式表达（简化说明）：
> Improvement = (S_raw - S_refined) / S_raw × 100%  
其中 S 为代码样本集的累计漏洞严重度得分。

## 六、主要结论与发现

1. **所有 LLM 输出均存在漏洞，本质不安全。**  
   - 无模型能在所有场景下生成安全代码。
   - 常见漏洞：输入验证缺陷（CWE-20）、硬编码凭据（CWE-798）、路径遍历（CWE-22）。

2. **微调（Fine-Tuning）效果最佳。**  
   - 总体漏洞严重度平均下降 **约 82%**。  
   - 能完全消除 SQL 注入与不安全反序列化类漏洞（CWE-89, CWE-502）。  

3. **提示策略中以 Meta Prompting 最优。**  
   - 相比其他提示法，MP 平均减少约 46–69% CWE 严重度。  
   - 但在复杂输入验证类 CWE 上仍不足。

4. **链式思维提示（CoT）改善中等但不稳定。**
   - 对逻辑推理型漏洞（如认证缺失）有效；
   - 对复杂语义缺陷（如输入清理）效果有限。

5. **负例提示（NEP）最不稳定。**  
   - 某些场景甚至引入更多漏洞。

6. **副效应显著：修复可能引入新漏洞。**
   - 特别是输入验证代码可能导致正则表达式性能问题（新 CWE-1333）。

7. **语言差异显著。**
   - **安全性排序：Go > Python > Java > JavaScript。**
   - 动态类型语言整体更易含漏洞。
