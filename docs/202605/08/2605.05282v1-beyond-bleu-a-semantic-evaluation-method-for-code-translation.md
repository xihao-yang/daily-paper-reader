## 摘要
代码翻译是大型语言模型（LLM）的核心能力之一。然而，评估翻译的正确性仍然具有挑战性，因为常用的指标（如 BLEU）仅衡量句法相似性，而忽略程序语义。我们提出了一种新的代码翻译任务评估方法，强调语义等价性而非表层字符串相似性。我们的方法将既有的编译器测试方法学应用到新的领域，使我们能够评估针对二进制提升任务（即将二进制文件反编译为更高级表示）微调的 LLM。我们引入了一个语义正确性评分，定义为生成正确执行结果的翻译比例，并通过对基于 LLM 和启发式的反编译器进行评估展示其应用。研究结果表明，基于 LLM 的方法显著优于启发式方法，而 BLEU 得分与语义正确性之间几乎无相关性（r = -0.127 至 0.354），表明句法指标无法预测功能准确性。

## Abstract
Code translation is one of the core capabilities of LLMs. However, evaluating the correctness of translations remains difficult, as commonly used metrics such as BLEU measure only syntactic similarity, disregarding program semantics. We propose a novel evaluation methodology for code translation tasks, emphasizing semantic equivalence over surface-level string similarity. Our approach applies established compiler testing methodology to a new domain, allowing the assessment of an LLM fine-tuned for binary lifting tasks (i.e. decompiling binaries to higher-level representations). We introduce a semantic correctness score, defined as the proportion of translations that produce correct execution outcomes, and demonstrate its application by evaluating LLM-based and heuristic decompilers. Our findings show that LLM-based approaches significantly outperform heuristic ones, while BLEU scores show negligible correlation with semantic correctness (r = -0.127 to 0.354), demonstrating that syntactic metrics fail to predict functional accuracy.

## 一、研究问题与背景

- **核心问题**：传统的代码翻译评价指标（如 BLEU、CodeBLEU）主要依赖字符串或语法结构的相似度，无法反映程序**语义等价性**。这导致模型即使输出在语法上相似，也可能在功能上错误。
- **研究动机**：
  - 在跨语言代码迁移、反编译（binary lifting）等任务中，核心目标是保持执行语义不变。
  - 当前 BLEU 类指标无法正确预测翻译代码的**功能正确性**，可能出现：
    - 功能正确但得分低（低估）。
    - 功能错误但得分高（高估）。
  - 作者希望建立一种**能直接衡量程序语义是否保留的指标体系**。

## 二、方法论与核心思想

### 1. 方法总体框架
- 提出一种**基于编译器测试的语义等价评估方法**。
- 关键思想：借鉴编译器验证领域中**自动化随机程序生成与校验执行结果一致性**的技术。

### 2. 具体流程（见 Figure 1）
1. **随机程序生成**  
   - 使用 *Csmith* 自动生成随机 C 程序，这些程序在每条指令后计算**CRC 校验和（checksum）**。
2. **编译与基线执行**  
   - 将生成的程序分别在不同优化级别（-O0、-O3）下编译，得到参考校验和值。
3. **翻译 / 反编译步骤**  
   - 将编译后的二进制交由“被测反编译器”（包括 LLM 模型）反编译为高层语言代码。
4. **再编译与执行**  
   - 将反编译输出重新编译并执行，生成新的校验和。
5. **语义比较**  
   - 若反编译后执行的校验和与参考值一致 ⇒ 视作语义等价。

### 3. 语义正确性得分（Semantic Correctness Score）
定义如下：

\[
\text{Semantic Score} = \frac{\text{语义等价（校验和正确）的程序数量}}{\text{总测试程序数量}}
\]

- 取值范围 0～1，越接近 1 表示语义保持越好。

## 三、实验设计

### 1. 实验场景与数据集
- **任务类型**：反编译（Decompilation / Binary Lifting）。
- **输入输出**：x86 汇编 → LLVM IR。
- **测试数据集**：自动生成的 1024 个随机 C 程序作为基准。

### 2. 对比模型
- **LLM-based 方法**  
  - Meta 的 **LLMCompiler (13B 参数)**，专为二进制提升任务微调。
- **启发式方法**
  - **RetDec**（Avast 开源反编译器）
  - **McToll**（LLVM 官方工具）

### 3. 评价指标
- **主要：** 语义正确性分数（Semantic Correctness Score）  
- **参考：** BLEU-1、BLEU-4、CodeBLEU，用于相关性分析。

## 六、主要结论与发现

1. **BLEU 无法预测语义正确性**：  
   - 相关系数介于 -0.13～0.35，几乎无显著线性关系。
2. **LLM 方法显著优于启发式方法**：
   - 在 -O0 程序中语义正确率为 33.0%，在 -O3 为 62.8%；
   - RetDec 与 McToll 几乎在所有测试中失败（出现编译或运行错）。
3. **说明**：仅依赖语法或 token 层相似度的度量无法反映真正的功能精度。

## 七、优点与创新性

- **语义导向**：重视执行一致性而非文本相似性，是对 BLEU 的根本性突破。  
- **自动化与可扩展性**：通过 *Csmith* 自动生成无限程序样本，无需人工标注。  
- **可复现性**：实验完全可自动化、系统化，对模型评价稳定可靠。  
- **实践意义**：为 LLM 反编译与跨语言翻译提供更准确的性能评价标准。  
- **量化指标简洁明确**：语义正确性分数直观且可理解。

## 八、不足与局限

- **语言范围受限**：当前仅支持从 C 源生成测试样本，其他语言需定制化工具。  
- **训练数据分布差异**：生成程序可能不在 LLM 编译器的训练分布内，影响绝对分数解释。  
- **语义验证方式单一**：仅通过校验和匹配验证语义一致性，未覆盖 I/O、副作用、并发语义等复杂情形。  
- **评估模型有限**：仅评测一种 LLM 架构与两种启发式方法，样本多样性可进一步扩大。
