## 摘要
近年来，大型语言模型（LLMs）在自动程序修复任务上展现出了强劲的性能，尤其是在标准基准测试中。然而，这些基准仅在单一的标准形式的缺陷代码上评估模型，未能反映现实软件中常见的语法变化，从而使模型的鲁棒性几乎未被检验。在本研究中，我们构建了 HEJ-Robust ——一个基于 HumanEval-Java-Bug 的鲁棒性基准，通过八种保持语义的代码转换生成了 1,450 个变换实例。我们在该基准上评估了五个经过微调的 LLM，并显示在多种转换下模型性能下降超过 50%，这表明目前的基于 LLM 的程序修复模型对轻微的语法变化缺乏鲁棒性。

## Abstract
Recent Large Language Models (LLMs) have shown strong performance on automated program repair across standard benchmarks. However, these benchmarks evaluate models on a single canonical form of buggy code and do not reflect the syntactic variations commonly observed in real-world software, leaving robustness largely unexamined. In this work, we construct HEJ-Robust, a robustness benchmark built from HumanEval-Java-Bug using eight semantics-preserving code transformations, resulting in 1,450 transformed instances. We evaluate five fine-tuned LLMs on this benchmark and show that model performance drops by over 50% under several transformations, indicating that current LLM-based repair models lack robustness to minor syntactic variations.

## 二、方法论：HEJ-Robust 的构建与设计

### 核心思想
- 基于 **HumanEval-Java-Bug** 数据集，通过 **8 种保持语义不变的代码转换（semantics-preserving transformations）** 构造变体，从而生成一个可执行、可测试的鲁棒性基准。
- 设计旨在模拟真实开发中的语法差异，如命名习惯、循环重构、异常处理等。

### 八种语义保持转换
1. **局部变量重命名** — 使用上下文感知的命名生成替换变量名。  
2. **方法重命名** — 同样基于自然语言化策略生成函数名。  
3. **参数重命名** — 与变量命名策略一致。  
4. **插入日志语句** — 添加 `System.out.println("log");` 于方法起始，不改变输出语义。  
5. **插入 try-catch 块** — 在合法位置添加防御性结构。  
6. **布尔值交换** — 调整布尔变量初始值并使用逻辑取反确保语义一致。  
7. **循环结构交换** — `for` 与 `while` 互换保持逻辑等价。  
8. **条件重排序** — 调换比较两侧的操作数。

### 关键技术细节
- **代码解析与转换工具**：使用 *tree-sitter* 和 *JavaTransformer* 实现抽象语法树（AST）级修改。  
- **自然命名生成**：借助 *CodeBERT*、*GraphCodeBERT* 的嵌入空间相似度生成自然标识符，避免因不自然命名导致模型性能偏差。  
- **变换有效性控制**：每个程序仅应用一次转换、保证语法合法；若转换影响缺陷行则剔除。  
- **数据再标注**：人工重新标记 bug 位置，双人交叉验证确保一致性。  
- **任务定义**：保持原有 bug 修复测试机制，即预测修复代码并通过运行测试用例验证。

## 五、主要结论与发现

- LLM 修复模型在语法微小变化下**鲁棒性显著下降**：
  - 在“局部变量重命名”情境下，性能下降超过 **50%**。
  - 其他结构性变化（循环改写、尝试捕获插入等）也出现 **10%–40%** 的降幅。
- **模型规模与鲁棒性不成正比**：更大的模型（如 CodeT5-large）表现并不更稳健。
- **CodeBLEU 与功能正确性不一致**：语法相似度高不等于语义正确。
- 总体上表明当前 LLM 修复模型高度依赖具体 token 序列，对语法变体缺乏泛化能力。
