## 摘要
背景：软件缺陷在开发过程中仍是关键挑战，需要有效的自动程序修复（APR）技术。尽管基于大型语言模型（LLM）的APR系统显示出前景，现有研究主要聚焦于总体修复效果。关于缺陷复杂度、故障定位、推理设置以及修复成本效益的影响仍然缺乏充分探究。  目标：本研究对基于LLM的APR进行全面的实证分析，重点考察修复性能如何受缺陷复杂度、故障定位、推理设置与成本的影响。  方法：我们在三种LLM（DeepSeek、GPT、Llama）上评估两种APR技术（ChatRepair与CodeCorrector），并通过多维实证框架与统计分析，考察它们在不同缺陷复杂度与定位策略下的表现。  结果：尽管结构更复杂的缺陷与不精确的故障定位会增加修复难度，基于LLM的APR技术仍能取得具有竞争力的修复效果。不精确的故障定位会显著扩大不同APR技术之间的性能差距。此外，更高成本的LLM与更强的推理设置并不总能带来更好的成本效益，揭示了修复效果与计算成本之间非平凡的权衡。  结论：低成本的基于LLM的APR技术可修复超过50%的中等复杂度缺陷。随着故障定位精度降低，不同APR技术之间的修复效果差距进一步扩大。GPT-5分别比DeepSeek-V4-pro和DeepSeek-V3.2多修复7个和39个复杂缺陷；而DeepSeek-V3.2在总修复成本方面表现出最佳的成本效益。

## Abstract
Background: Software bugs remain a critical challenge in development, necessitating effective Automated Program Repair (APR) techniques. While Large Language Model (LLM)-based APR systems have shown promise, prior studies primarily focus on overall repair effectiveness. The effects of bug complexity, fault localization, reasoning settings, and repair cost-effectiveness remain insufficiently explored.   Aims: This study presents a comprehensive empirical analysis of LLM-based APR, focusing on how repair performance is shaped by bug complexity, fault localization, reasoning settings, and costs.   Method: We evaluate two APR techniques (ChatRepair and CodeCorrector) using three LLMs (DeepSeek, GPT, and Llama), and examine their performance across diverse levels of bug complexity and localization strategies through a multi-dimensional empirical framework and statistical analysis.   Results: Although structurally complex bugs and imprecise fault localization make repair more challenging, LLM-based APR techniques still achieve competitive repair effectiveness. Imprecise fault localization can substantially enlarge the performance gap between APR techniques. Furthermore, higher-cost LLMs and stronger reasoning settings do not consistently yield better cost-efficiency, revealing a nontrivial trade-off between repair effectiveness and computational cost.   Conclusions: Over 50% of moderately complex bugs can be repaired by low-cost LLM-based APR techniques. The repair effectiveness gap between APR techniques becomes larger as fault localization becomes less precise. GPT-5 repairs 7 and 39 more complex bugs than DeepSeek-V4-pro and DeepSeek-V3.2, respectively; whereas the total repair cost of DeepSeek-V3.2 shows the best cost-efficiency performance.

# 2. 方法论：核心思想、技术细节与流程
- 核心思路
  - 构建更具挑战性的算法型 C++ 缺陷数据集（来源于 AtCoder，2025年10月），并从“行/块级变化”和“AST 操作差异”两个维度刻画缺陷复杂度。
  - 在统一的实验基础设施下，对两类 LLM‑APR 框架（ChatRepair、CodeCorrector）与多家族 LLM（DeepSeek、GPT、Llama）进行系统评估；分层考察 FL 精度（行级、块级、无定位）与推理模式（启用/禁用推理），引入统一的成本效益度量。
- 关键技术细节
  - 数据与差异提取
    - 对同一参赛者的错误/正确提交配对为 “bug‑patch pair”；使用 git diff 生成差异；去除注释与冗余空行。
    - 定义每个 hunk 的修复行数：Nfixed = max(N+, N−)。
  - 缺陷复杂度建模（两维）
    1) Hunk‑line 维度（基于 git diff）
       - SHSL：单 hunk、单行修复；SHML：单 hunk、多行；MHSL：多 hunk、单行；MHML：多 hunk、多行。
       - 分类规则：依据 hunk 数量 H 与各 hunk 修复行数 L(hi) 判定（若任一 hunk 的 L(hi) > 1 则为多行型）。
    2) AST 操作类型维度（基于 srcML + GumTreeDiff）
       - 计算 AST 编辑操作集的多样性（insert/delete/relabel/move）来刻画结构复杂度；按操作类型数量分为 1‑op、2‑op、3‑op、4‑op。
  - 故障定位（FL）策略
    - 行级 FL：直接标注具体 buggy line。
    - hunk 级 FL：标注 buggy hunk 区段。
    - 无 FL：不提供定位提示。
  - APR 框架与提示设置
    - ChatRepair：迭代生成/修补，最多 3 轮对话；在更大规模实验中最多 10～13 轮；可在生成到首个可行补丁时停止以控成本。
    - CodeCorrector：两阶段（分析修复方向 + 生成补丁），遇到首个可行补丁即停止。
    - 提供问题背景、buggy 代码、编译错误信息和最多 3 个失败用例；沿用原论文提示词，不做模型特定参数调优。
  - LLM 与推理设置
    - DeepSeek‑V3.2：chat 与 reasoner 两变体；DeepSeek‑V4‑pro：thinking_type 控制推理，reasoning_effort 设为 high/max。
    - GPT‑5 / GPT‑4o‑mini：通过 reasoning.effort 控制（medium/high/xhigh）；Llama‑3.1 无显式推理控制。
    - 全部温度设为 1.0。
  - 成本效益度量（统一到美元）
    - Repaired Bugs/$：每美元修复的缺陷数。
    - Attempts/$：每美元可支持的修复尝试数。
    - API 成本由输入/输出 token 用量与厂商单价计算。
  - 一致性度量（CCR）
    - CCR = r/k，其中 k 为修复后代码总行数，r 为保留原结构的代码行数量；用以衡量补丁结构一致性。
  - 统计分析
    - 卡方检验（2×2 配对）比较不同复杂度类别的修复率差异。
    - 逻辑回归评估 FL 精度下降对成功修复的影响（报告 OR 与 p 值）。

# 6. 主要结论与发现
- 复杂度影响（RQ1）
  - SHSL 与 1‑op 缺陷最易修复（修复率分别约 78.5%、75.2%，对其它类别差异显著，p<0.005）。
  - 中等复杂度类别（SHML、MHSL、MHML、2‑op、3‑op）修复率均超过 50%；4‑op 最具挑战，但仍保持“可观”修复率。
  - 低成本 LLM‑APR 在结构复杂缺陷上仍有稳定修复能力。
- FL 影响（RQ2）
  - FL 越精确，修复率与补丁结构一致性（CCR）越高；行级 FL 下两框架修复率相近，但在 hunk 级与无 FL 时差距显著扩大（ChatRepair 明显更稳健）。
  - 随复杂度升高，对 FL 精度的依赖相对降低，修复更依赖程序理解与推理能力（逻辑回归 OR 在简易缺陷更低且显著）。
- 成本‑效果权衡（RQ3）
  - 更昂贵/更强推理并非总是更高性价比：DeepSeek‑V3.2‑chat 在 Repaired Bugs/$ 与 Attempts/$ 上显著优于 GPT‑4o‑mini，且整体成本远低于 GPT‑5 与 DeepSeek‑V4‑pro。
  - 推理模式收益因 LLM 家族而异：GPT‑5 启用高推理仅少量新增修复（+3），DeepSeek‑V3.2/‑V4‑pro 在推理模式下大幅提升（+64、+81）。
  - 两阶段策略更优：先用低成本 LLM（如 DeepSeek‑V3.2 非推理）覆盖多数，再用高性能 LLM（如 GPT‑5 非推理）兜底剩余，综合性价比更佳。
- 顶层结论
  - 超过一半的中等复杂度缺陷可被低成本 LLM‑APR 成功修复；
  - FL 精度下降会显著放大不同 APR 框架之间的性能差距；
  - GPT‑5 在修复复杂缺陷数上领先（比 DeepSeek‑V4‑pro 多 7 个、比 DeepSeek‑V3.2 多 39 个），但 DeepSeek‑V3.2 的总体成本效益最佳。
