## 摘要
近年来，自动程序修复（APR）受益于大型语言模型（LLMs），但其有效性高度依赖于修复上下文。现有基于 LLM 的 APR 方法存在因果鸿沟：测试上下文可能含噪或不完整，而基于静态分析得到的源码上下文往往包含无关且未执行的代码，从而误导 LLM，偏离对真正根因的识别。为解决这一问题，我们提出 CausalRepair，这是一种以对话为驱动、基于最小因果上下文的 APR 框架，即仅保留用于解释故障所需的关键依赖。CausalRepair 采用双切片策略：具备上下文感知的静态切片用于提纯测试语义，而基于执行轨迹的动态切片用于捕获源码中的精确运行时依赖。二者共同构建紧凑且因果相关的上下文，以引导迭代式修复。我们在 Defects4J V1.2、V2.0 以及 Defects4J-Trans 上使用 DeepSeek-V3 对 CausalRepair 进行评估。CausalRepair 在 Defects4J 上正确修复了 313 个缺陷，优于 ReinFix 和 TSAPR 等最新方法，并将平均修复成本降低至每个缺陷 0.029 美元。

## Abstract
Automated Program Repair (APR) has recently benefited from Large Language Models (LLMs), yet their effectiveness heavily depends on repair context. Existing LLM-based APR methods suffer from a causality gap: test contexts can be noisy or incomplete, while source contexts derived from static analysis often contain irrelevant and unexecuted code, misleading LLMs from identifying the true root cause. To address this issue, we propose CausalRepair, a conversation-driven APR framework based on minimal causal context, i.e., the essential dependencies required to explain a failure. CausalRepair employs a dual-slicing strategy: context-aware static slicing purifies test semantics, while execution-trace-based dynamic slicing captures precise runtime dependencies in source code. Together, they construct compact, causally relevant contexts to guide iterative repair. We evaluate CausalRepair on Defects4J V1.2, V2.0, and Defects4J-Trans using DeepSeek-V3. CausalRepair correctly fixes 313 bugs on Defects4J, outperforming state-of-the-art approaches such as ReinFix and TSAPR, while reducing the average repair cost to $0.029 per bug.

## 1. 核心问题与整体含义（研究动机与背景）
- 动机
  - LLM 驱动的自动程序修复（APR）近年成为主流，但修复效果高度依赖“修复上下文”的质量。
  - 现有上下文构造存在因果鸿沟：
    - 测试侧：要么提供完整测试导致多断言噪声与语义歧义，要么只给失败断言导致依赖缺失，难以明确违反的行为约束。
    - 源码侧：静态分析检索引入静态过近似（over-approximation），包含未执行路径与无关代码，掩蔽根因。
- 核心问题
  - 如何为 LLM 构造一个与失败“因果相关”的最小上下文，使其能沿着可靠的因果链定位根因并生成正确补丁？
- 整体含义
  - 提出“最小因果上下文”概念：解释特定失败所必需的最小依赖集合。
  - 以“对话式修复 + 双端切片”为主线，精炼并结构化失败相关的测试与运行时源码依赖，形成高信噪比提示，持续引导 LLM 收敛到正确修复。

## 2. 方法论：核心思想、关键技术细节与算法流程
- 核心思想
  - 用“双切片”构建最小因果上下文：
    - 测试侧：语境感知静态切片，去噪并保留失败断言所需的初始化/状态依赖，澄清测试语义与违反约束。
    - 源码侧：基于失败触发的真实执行轨迹做动态切片，严格沿实际路径回溯，仅保留直接影响失败断言的因果语句。
  - 再通过对话式迭代修复和补丁增广，提高收敛与正确率，降低过拟合。

- 关键技术细节
  - 测试侧“语境感知静态切片”
    - 将测试函数建模为语句序列 T=⟨s1,…,sn⟩，失败行 s_fail。
    - 构建系统依赖图（SDG）：包含数据依赖和控制依赖边。
    - 切片准则 κ=⟨s_fail, V_fail⟩，V_fail 为失败行引用变量集合。
    - 取 s_fail 的后向传递闭包（数据/控制依赖）得到 S_intra，去除与失败无关的测试场景。
    - 递归解析方法/字段的跨过程依赖，得到外部依赖集合 E，最终形成测试上下文 C_test=S_intra∪E，并附带真实失败行与错误信息。
  - 源码侧“执行轨迹动态切片”
    - 使用 Slicer4J 运行经 C_test 驱动的程序，记录执行事件序列 T=⟨e1,…,ek⟩。
    - 将 s_fail 映射到其最后一次运行事件 e_target，作为动态切片准则 κ_dyn=e_target。
    - 在动态依赖图（DDG）上做后向切片：仅保留对 e_target 有动态数据/控制依赖的事件，并映射回静态语句集合 S_dyn（即最小因果语句集）。
    - 仅保留“实际执行且对失败有因果贡献”的代码，滤除死代码与未致因的执行。
  - AST 结构化重建与语义锚注入
    - 将分散的 S_dyn 按文件/类/方法层级重建“骨架树”，回填切片语句，删除未选语句，保证结构完整与上下文连贯。
    - 注入文件路径、Javadoc/注释（意图锚）、相对行号等多维元信息，强化 LLM 的空间定位与意图理解，避免“lost in the middle”。
  - 对话式迭代修复（Generate–Validate–Feedback）
    - 初始化提示包含：重建后的 C_source + C_test + 待修复函数。
    - 每轮生成单一候选补丁，立即编译/执行测试验证。
    - 若失败，则构造反馈（错误日志、失败测试、上轮错误补丁）继续迭代，直至达最大轮次或获得可行补丁。
  - 补丁增广（降低过拟合）
    - 以已通过测试的可行补丁为“高价值参考”，要求 LLM 生成多样等价变体并验证，扩增正确补丁的概率。

- 算法流程（文字版）
  - Phase 1：构造最小因果上下文
    1) 定位失败测试与失败语句；2) 测试侧静态切片提纯 C_test；3) 用 C_test 驱动执行，动态切片得 S_dyn；4) AST 重建与语义锚注入，形成 C_source；5) 组合 C_test 与 C_source 构造初始提示。
  - Phase 2：对话式迭代修复
    1) 设定修复尝试数 m，单次迭代上限 n；2) 逐轮生成补丁并验证；3) 失败则基于负反馈继续对话；4) 成功则进入增广。
  - Phase 3：补丁增广
    1) 以可行补丁为参考，生成若干变体；2) 验证通过者作为输出集。

- 关键超参与预算
  - 统一使用温度=1.0；完美定位（perfect FL）。
  - 修复预算：m=5（尝试次数）、n=3（每次对话轮数），增广阶段生成 10 个变体；最大探索补丁数约 25（5×3+10）。

## 7. 优点（方法与实验亮点）
- 因果导向的上下文构造

  - AST 骨架重建 + 语义锚（文件路径、Javadoc、相对行号）提升可读性与空间定位，缓解长上下文“中部遗忘”。

  - 利用负反馈持续自纠；以可行补丁为锚点做局部变体探索，提升正确修复概率。

## 8. 不足与局限
- 语言与工具依赖
  - 当前实现仅支持 Java，依赖 Slicer4J 动态切片工具；迁移到其他语言需对应的高精度动态切片生态。
- 失败测试可用性假设
  - 方法属于“测试驱动 APR”，依赖已有可复现的失败测试；对缺少显式失败用例（如仅有自然语言 issue）的场景不直接适用。
- 定位设置与主结果
  - 主结果多在完美定位下获得；尽管提供了现实定位补充，但与真实项目复杂性仍有差距。
- 动态切片开销与失败
  - 设定了 5 分钟切片超时，超时/崩溃会降级为无动态上下文，可能影响个别样例效果。
- 语料污染与泛化
  - 已用 Defects4J-Trans 降低污染影响，但对更广泛、更新的真实项目仍需持续验证。
- 多文件/多位置修复能力
  - 虽在 GitBug-Java 中对 MF/跨文件有一定效果，但整体框架仍以函数级入口为主，跨范围复杂修改的能力与策略可进一步增强。
