## 摘要
Delta 调试提供了一种自动化方法，用于在保持某种特定性质的前提下最小化程序输入。然而，其有效性从根本上依赖于测试预言机（test oracle）的可用性，以判断约简后的输入是否仍然保留该特定性质。因此，预言机问题极大地限制了现有 Delta 调试技术的适用性，尤其是在无法直接判定输出正确性的预言机缺失程序中。为了解决这一问题，本文提出了一种新的方法 DDMT，以增强 Delta 调试的适用性，特别是促进其在预言机缺失程序中的应用。我们的核心思想是重新设计一种独立于预言机的测试函数，并将其集成到 Delta 调试的约简过程中，从而无需测试预言机即可完成性质保持验证。为此，DDMT 采用了变形测试（metamorphic testing）技术，这是一种基于性质且独立于预言机的测试方法。DDMT 构建了一个基于变形测试的测试函数，并以其替代 Delta 调试原先采用的测试函数。实验在 66 个测试对象上评估了 DDMT，涵盖预言机可用与预言机缺失两种场景，并结合不同的 Delta 调试方法进行测试。结果表明，DDMT 能够增强 Delta 调试的适用性，同时通常还能保持或提升约简效果与查询效率。此外，与相关的 Delta 调试方法相比，在适当配置下，DDMT 还能够实现性能提升。

## Abstract
Delta debugging provides an automatic way to minimize a program input while preserving a certain property. However, its effectiveness fundamentally relies on the availability of test oracles to determine whether a reduced input still preserves the specific property. Consequently, the oracle problem substantially limits the applicability of existing delta debugging techniques, particularly for oracle-deficient programs where output correctness cannot be directly determined. To address this problem, this paper proposes a novel approach, DDMT, to enhance the applicability of delta debugging, especially facilitating its application to oracle-deficient programs. Our key insight is to redesign an oracle-independent test function and incorporate it into the reduction procedure of delta debugging such that the property-preservation validation can be accomplished without requiring a test oracle. To this end, DDMT employs the technique of metamorphic testing, which is a property-based and oracle-independent testing method. It establishes a metamorphic testing-based test function, using it as a replacement for the original test function adopted by delta debugging. The experiments evaluate DDMT on 66 subjects across both oracle-available and oracle-deficient scenarios, with different delta debugging approaches. The results positively confirm that DDMT can enhance the applicability of delta debugging while often preserving or improving reduction effectiveness and query efficiency. Furthermore, compared to the relevant delta debugging approaches, DDMT is also able to achieve performance improvements with proper configurations.

### 研究背景

Delta Debugging（DD）是一类经典的自动化输入约简技术，其目标是：

- 最终得到“最小失败输入（minimal failure-inducing input）”。

其核心代表算法是 `ddmin`。

该技术广泛用于：

- failure reproduction（故障复现）
- bug localization（缺陷定位）
- GUI trace reduction
- compiler bug reduction
- web event simplification
- AI system debugging 等

近年来也出现了大量增强版本：

- HDD

这些工作主要优化：

- 约简效果（更小）
- 查询效率（更少测试）
- 结构感知能力（syntax-aware）

### 核心问题：Test Oracle Problem

现有 Delta Debugging 有一个根本性限制：

它依赖“测试预言机（test oracle）”。

即：

对于每个候选输入，系统必须知道：

- 输入是否仍然“失败”
- 是否仍然保留目标性质

传统 DD 依赖：

- crash oracle
- exit code
- expected output

但现实中很多程序：

- 没有正确输出
- 输出难验证
- 正确行为不可自动判断

典型包括：

- compiler silent bugs
- machine learning systems
- scientific software
- optimization systems

因此：

“缺乏 oracle” 极大限制了 DD 的适用范围。

# 2. 方法论

# 2.1 总体思想

DDMT 的核心思想：

用“变形测试（Metamorphic Testing）”替代传统 oracle。

即：

传统 DD：
- 判断“输入是否失败”

DDMT：
- 判断“输入对应的 Metamorphic Relation 是否被违反”

因此：

不需要知道正确输出。

---

# 2.2 回顾 ddmin

传统 ddmin：

输入：
- 程序 P
- 输入 t
- oracle o

定义测试函数：

```text
test(t, P, o)
```

输出：

- F（Fail）
- T（Pass）

ddmin 的流程：

1. 将输入切分
2. 删除一部分
3. 测试是否仍失败
4. 若仍失败则继续缩减
5. 直到无法继续

核心依赖：

```text
test(candidate) == Fail
```

因此 oracle 是必需的。

---

# 2.3 Metamorphic Testing（MT）

MT 的思想：

不验证“输出是否正确”，而验证：

“多个输入输出之间是否满足某种关系”。

这个关系称为：

Metamorphic Relation（MR）

例如：

对于 lexical analyzer：

“添加 comment 不应改变分析结果”

则：

- 原输入 → source input
- 修改后输入 → follow-up input

如果：

输出违反关系

则说明程序存在 bug。


# 2.5 DDMT 的测试函数

定义：

```text
mrtest(t, P, r)
```

其中：

- t：输入
- P：程序
- r：MR

流程：

## Step 1：生成 follow-up input

```text
w = r(t)
```

根据 MR 从 t 构造新输入。

---

## Step 2：执行程序

分别执行：

```text
P(t)
P(w)
```

得到：

- source output
- follow-up output

---

## Step 3：检查 MR

检查：

```text
MRCheck(a, b, r)
```

若违反：

```text
return V
```

否则：

```text
return S
```
