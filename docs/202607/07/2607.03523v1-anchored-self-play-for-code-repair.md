## 摘要
代码修复是语言模型（LM）的一项重要能力：给定一个存在缺陷的程序及其单元测试，语言模型必须生成一个能够通过测试的修复版本。由于代码修复数据有限，我们希望通过使用语言模型生成“缺陷—修复”任务来扩展监督信号。我们提出了“生成器—修复器自对弈”（generator–fixer self-play）方法，其中单个模型通过强化学习同时学习生成缺陷并修复它们。随着修复器能力的提升，生成器会适应性地产生更困难的缺陷，从而形成一种自动课程机制。为了测试这种课程是否具有泛化能力，我们提出了 BugSourceBench，这是一个覆盖真实缺陷来源的修复基准，包括人工编写代码中的缺陷、语言模型生成代码中的缺陷，以及人工编辑后的语言模型生成代码中的缺陷。在 BugSourceBench 上，我们发现自对弈会逐渐偏向困难但不真实的缺陷：虽然在合成缺陷上的表现有所提升，但在人类编写的缺陷上的表现却下降了。为此，我们提出了锚定自对弈（Anchored Self-Play，ASP），通过加入少量参考集来约束自对弈：在生成阶段加入基于代码嵌入相似度的奖励，并在修复器训练中混入参考缺陷。跨不同缺陷来源，ASP 均取得了最佳修复率，相较于标准自对弈，其平均修复率提升了相对值 +24% / 绝对值 +7.0 个百分点，并且在人类与语言模型产生的缺陷上均获得了性能提升。

## Abstract
Code repair is an important capability for language models (LMs): given a buggy program and unit tests, an LM must produce a fixed program that passes the tests. Because code repair data is limited, we aim to scale supervision by using an LM to generate bug--fix tasks. We propose __generator--fixer self-play__, in which a single model is trained with reinforcement learning to generate bugs and fix them. As the fixer improves, the generator adapts to produce more difficult bugs, yielding an automatic curriculum. To test whether this curriculum generalizes, we introduce BugSourceBench, a repair benchmark spanning realistic bug sources: bugs in human-written code, LM-generated code, and human-edited LM-generated code. On BugSourceBench, we find that self-play drifts toward difficult but unrealistic bugs, improving on synthetic bugs but degrading on human-authored ones. We propose Anchored Self-Play (ASP), which anchors self-play with a small reference set by adding a code-embedding similarity reward for generation and mixing reference bugs into fixer training. Across bug sources, ASP achieves the best fix rates, improving average fix rate over standard self-play by $+24\%$ relative / $+7.0$ pp absolute, with gains on bugs from both LMs and humans.

# 2. 方法论

# 2.1 Generator–Fixer Self-Play

论文提出：

- 一个模型同时扮演：
  - Generator（生成 bug）
  - Fixer（修复 bug）

训练流程：

---

## Step 1：生成 bug

给定：

- 任务描述 x
- 正确代码 c*

生成器生成：

b ~ πG(· | x, c*)

要求：

- 程序可运行
- 至少有一个 unit test fail

否则视为 invalid bug。

---

## Step 2：执行测试

运行：

v(x,b)

返回：

- pass/fail
- error trace

---

## Step 3：修复 bug

Fixer 输入：

- task
- buggy code
- test trace

输出：

y ~ πF(· | x,b,o(x,b))

若：

v(x,y)=1

则修复成功。

# 2.2 Fixer Reward

Fixer 奖励非常直接：

rF(x,b,y)=v(x,y)

即：

- 通过测试 = 1
- 否则 = 0

# 2.3 Generator Reward（难度奖励）

作者不希望 bug：

- 太简单
- 太难

因此定义：

ρ(x,b)

表示 fix rate：

- 对同一个 bug 修 K 次
- 看有多少次修成功

即：

ρ = 平均 pass rate

---

生成器奖励：

- ρ=1：
  bug 太简单
- ρ=0：
  bug 太难
- 中间难度：
  奖励最高

因此：

Generator 学习生成：

“当前 fixer 勉强能修”的 bug。

这形成自动 curriculum。

---

作者发现：

- 是否 functional failure

却不能验证：

- 是否 realistic

因此 generator 会学到：

- 奇怪但能骗测试的 bug；
- 与真实 bug 分布逐渐偏离。

这导致：

- synthetic benchmark 提升；
- human bug repair 下降。

# 2.5 Anchored Self-Play（ASP）

ASP 是论文核心贡献。

目标：

> 用少量真实 bug 约束 self-play。

它包含两个关键机制。

---

# 2.5.1 Reference Mixing

训练 fixer 时：

以概率 pmix：

不使用 generator 生成的 bug，

而是使用：

reference bug。

作用：

- 保证 fixer 始终看到真实 bug；
- 防止训练分布漂移。

注意：

只更新 fixer；
不更新 generator。

作者实验发现：

更新 generator 会导致性能下降。

---

# 2.5.2 Similarity-Guided Reward

作者进一步约束 generator：

- 生成的 bug
- 应该接近真实 bug 风格。

做法：

---

## (1) diff embedding

计算：

correct code ↔ buggy code

之间的 unified diff。

再使用：

voyage-code-3 embedding

编码。

---

## (2) kNN similarity

与 reference bug diff embedding：

做 kNN cosine similarity。

得到：

sim(b)

---

## (3) centered shaping reward

为了稳定训练：

作者没有直接用 similarity。

而是：

δt(b)=sim(b)-Bt

其中：

Bt 是 EMA baseline。

最终 generator reward：

rG = base_reward + λ·clip(δt)

即：

只鼓励：

“比当前平均更真实”的 bug。

这是比较漂亮的 reward shaping 设计。
